# 备份、恢复与运维

## 持久化目录

开发环境默认把私密图片和导出文件保存在 `apps/api/.private-assets` 与 `apps/api/.private-exports`。生产环境不允许依赖这两个源码目录，启动 API 前必须配置：

```text
DIARY_ASSET_STORAGE_PATH=/srv/diary/private-assets
DIARY_EXPORT_STORAGE_PATH=/srv/diary/private-exports
```

两个值必须是绝对路径，并应挂载到独立持久卷。数据库备份必须和这两个目录作为同一批次处理，因为数据库中保存着文件键；只备份数据库或只复制文件都不是完整备份。

## 本地恢复演练

Docker PostgreSQL 健康后，在项目根目录运行：

```powershell
npm run db:restore-drill
```

脚本只创建名称带随机标识的独立临时数据库和 `.runtime/backup-restore-drill-*` 临时目录，不读取、修改或删除 `diary_dev`。流程如下：

1. 对临时源数据库执行全部顺序迁移。
2. 写入账号、结构化日记、标签、图片记录、导出记录及四个私密文件。
3. 使用 PostgreSQL 自带 `pg_dump` 创建自定义格式备份，并复制图片和导出目录。
4. 删除临时源数据库和源文件，确保不是在原位置读取。
5. 把备份恢复到另一个空数据库和新的文件目录。
6. 校验迁移数量、日记内容、关联关系、文件键和每个文件的 SHA-256。
7. 清理两套临时数据库及目录，在 `artifacts/backup-restore-drill-report.json` 留下不含正文和凭据的结果。

失败会返回非零退出码，不能将失败报告成可恢复。报告只证明本机隔离演练；不证明云端定时任务、备份加密、保留周期、跨区域副本、生产权限、恢复时间目标或告警已经验收。

## 正式环境仍需完成

- 为 PostgreSQL、图片目录和导出目录建立同一批次的定时备份，并对备份静态加密。
- 把备份存到与运行服务器故障域不同的位置，限制读取和删除权限。
- 定期恢复到隔离环境，用账号、日记、附件和迁移校验判定成功。
- 监控 API 就绪状态、数据库连接、同步/导出/清理 worker、磁盘容量、备份失败和恢复演练失败。
- 记录发布版本、迁移版本、回滚方案、恢复点目标和恢复时间目标。

正式恢复可能覆盖数据库和持久卷，必须由运维人员明确选择备份与目标后执行；项目不会用默认命令自动清空生产数据。

## 健康与积压监控

API 提供两个只允许回环地址访问的运维入口：

- `/api/v1/health/ready`：验证数据库连接可用。
- `/api/v1/health/operations`：只返回快照、导出、注销、失败图片和逾期回收站的聚合计数，不返回账号、标题或正文。

`operations` 返回 `attention` 时应由外部监控系统触发告警，并携带响应中的 requestId 关联服务端结构化日志。接口本身不负责发送短信、邮件或第三方通知；告警接收方和阈值仍要在部署环境配置。
