# 第 14 课：离线缓存与可靠同步

这一课解决一个容易被误解的问题：点击“保存”后，数据到底保存在哪里？可靠的离线日记必须分别表达“本机已保存”“等待上传”“服务器已确认”和“发生冲突”。

配套目录：`learning/lesson-14`  
启动命令：`npm run learn:14`  
检查命令：`npm run check:learn:14`  
地址：`http://127.0.0.1:4190`

> 这一课让已经打开的页面在断网时继续写作。离线刷新后还能重新打开整个页面，需要第 15 课的 Service Worker。教学数据与正式日记完全隔离。

## 1. 本课三个核心概念

1. IndexedDB：浏览器内可以保存对象和事务的数据库。
2. Outbox：把尚未被服务器确认的操作排队保存。
3. 幂等与版本：同一请求重试不重复创建，旧版本不覆盖新版本。

数据流：

```text
用户点击保存
  ↓ 同一个 IndexedDB 事务
entries 写入本机副本 + outbox 写入待上传操作
  ↓ 有网络时逐项发送
POST /api/mutations
  ↓
服务器检查 clientRequestId 和 baseRevision
  ↓
成功：删除 outbox，标记已同步
冲突：保留本机副本，标记发生冲突
失败：保留 outbox，稍后重试
```

## 2. 为什么 localStorage 不够

`localStorage` 适合第 7 课的小数据练习，但它：

- 只能保存字符串。
- 没有跨多张表的事务。
- 大量内容会阻塞主线程。
- 查询和索引能力很弱。

IndexedDB 支持对象存储、索引和事务，更适合离线应用。本课使用两张对象仓库：

| 对象仓库 | 主键 | 作用 |
| --- | --- | --- |
| `entries` | `id` | 当前设备可见的日记副本 |
| `outbox` | `clientRequestId` | 服务器尚未确认的操作 |

## 3. IndexedDB 基本关键字

打开数据库：

```js
const request = indexedDB.open('diary-lesson-14', 1);
```

| 名称 | 含义 |
| --- | --- |
| `onupgradeneeded` | 首次创建或版本升级时建立结构 |
| `onsuccess` | 请求成功事件 |
| `onerror` | 请求失败事件 |
| `transaction()` | 开启事务 |
| `objectStore()` | 取得对象仓库 |
| `put()` | 新增或替换同主键对象 |
| `getAll()` | 读取所有对象 |
| `delete()` | 删除指定主键对象 |
| `keyPath` | 对象中作为主键的属性 |

IndexedDB 原生 API 基于事件，所以本课把请求包装成 Promise，才能配合 `await`：

```js
const requestResult = request => new Promise((resolve, reject) => {
  request.onsuccess = () => resolve(request.result);
  request.onerror = () => reject(request.error);
});
```

## 4. 为什么本机日记和 Outbox 必须同事务

错误做法是先保存日记，过一会儿再保存上传任务。如果中间断电，日记虽然在本机，但系统永远不知道它需要上传。

正确做法：

```js
const tx = db.transaction(['entries', 'outbox'], 'readwrite');
tx.objectStore('entries').put(localEntry);
tx.objectStore('outbox').put(syncJob);
```

只有整个事务完成，两个写入才同时生效。事务失败时两者都不会部分留下。

## 5. 三种同步状态

| `syncState` | 含义 | 能否说已在云端 |
| --- | --- | --- |
| `pending` | 本机保存，等待或正在上传 | 不能 |
| `synced` | 服务器明确返回成功 | 可以 |
| `conflict` | 服务器存在其他版本，停止覆盖 | 不能，需要选择 |

“网络请求已经发出”不等于“服务器保存成功”。超时响应属于未知结果，客户端必须使用同一个请求编号重试查询，而不是新建另一个请求。

## 6. Outbox 操作的字段

```js
const job = {
  clientRequestId: crypto.randomUUID(),
  operation: 'upsert',
  entry: {
    id,
    entryDate,
    title,
    content,
    baseRevision
  },
  createdAt: new Date().toISOString()
};
```

- `clientRequestId`：一次逻辑保存的固定请求编号。
- `operation`：操作类型，本课只实现 `upsert`。
- `baseRevision`：编辑开始时看到的服务器版本。
- `createdAt`：用于按产生顺序处理队列。

重试时必须复用原来的 `clientRequestId`。如果每次重试都生成新编号，服务端无法判断它们是不是同一次保存。

## 7. 服务端幂等

服务端 SQLite 使用 `mutations.client_request_id` 唯一主键，并保存第一次成功响应：

```sql
SELECT response_json
FROM mutations
WHERE client_request_id = ?;
```

如果编号已经处理过，服务端直接返回相同业务结果，不再次写入日记。本课自动检查会把同一个请求发送两次，并确认只有一篇日记。

幂等不是“忽略所有重复内容”。两篇文字完全相同但请求编号不同，仍可能是用户确实写了两篇记录。

## 8. 乐观版本冲突

客户端编辑某篇日记时记住 `baseRevision`。服务器写入前比较：

```text
客户端 baseRevision == 服务器当前 revision → 可以写入
客户端 baseRevision != 服务器当前 revision → 返回 409
```

HTTP 409 表示当前状态冲突。服务端返回当前版本，客户端保留本机副本并显示“发生冲突”，不能静默覆盖。

为什么不能用“最后写入者获胜”：两台设备都可能写了重要内容，按时间覆盖会永久丢失其中一份。

## 9. 拉取服务器快照时的合并规则

本课采用最小规则：

- 本机没有该日记：接受服务器版本。
- 本机状态是 `synced`：可以刷新为服务器版本。
- 本机状态是 `pending`：不能被快照覆盖。
- 本机状态是 `conflict`：不能被快照覆盖。

正式产品还会有分页增量同步、删除墓碑、每账号命名空间、图片队列和冲突合并页面。本课先把“不丢本机修改”学清楚。

## 10. 网络状态的真实边界

`navigator.onLine` 只能表示浏览器认为网络接口是否在线，不能证明 API 一定可达。即使它为 `true`，服务器仍可能超时或返回 500。

因此同步代码必须以实际请求结果为准：

```js
try {
  await upload(job);
  // 服务器明确成功后才能删除 outbox
} catch (error) {
  // 保留 outbox，允许稍后重试
}
```

页面中的“暂停联网请求”是教学开关，用来稳定观察排队状态；它不伪装成系统真的断网。你也可以通过开发者工具 Network → Offline 测试真实断网。

## 11. 亲手实验

```powershell
npm run learn:14
```

打开 `http://127.0.0.1:4190`：

1. 等待种子日记显示“已同步”。
2. 点击“暂停联网请求”。
3. 写标题和正文，点击“先保存到本机”。
4. 观察状态为“待同步”，队列数量为 1。
5. 点击“恢复联网并同步”。
6. 等待状态变为“已同步”，队列数量变为 0。
7. 在线刷新页面，确认服务器快照仍包含该日记。

冲突实验：打开两个标签，让它们都读取同一版本；暂停第二个标签，先在第一个标签编辑并同步，再让第二个标签提交旧版本。第二个标签必须显示冲突，不能覆盖第一个标签。

## 12. 常见错误

### 一上传成功就重新生成请求编号

超时后无法知道服务器是否处理过。请求编号应在本机入队时生成，直到该操作得到确定结果前保持不变。

### 在网络失败时删除 Outbox

这会造成不可恢复的数据丢失。只有确定成功或用户明确解决冲突后才能移除。

### 拉取快照覆盖 pending

这会把用户刚刚离线写的内容替换成旧云端版本。合并前必须检查本机状态。

### 把 `online` 事件当成同步成功

它只代表网络可能恢复。仍需发送请求并等待服务端响应。

### 离线刷新页面打不开

这是第 14 课的预期边界：IndexedDB 保存了数据，但 HTML/JS 应用外壳还没有离线缓存。第 15 课使用 Service Worker 解决。
