# 日记网站与移动应用学习重构方案

> 2026-09-08 补充：本文继续作为基础课程路线，不作为正式产品的完整范围。最新功能、页面、接口和阶段验收以 [产品设计方案 v2](产品设计方案-v2.md) 及其配套文档为准。localStorage 与服务端 SQLite 是学习练习；正式服务端使用 PostgreSQL，Web 使用 IndexedDB，手机 App 使用本地 SQLite。电脑交付为浏览器 + 可安装桌面 PWA，手机交付为 Android / iOS App。下文“第一版”指前几课的学习版，不表示取消图片、富文本、同步等正式功能；第三方登录则始终不在本次产品范围。

## 1. 重新设计的目标

这次重构有两个同等重要的目标：

- 写出一个真正能使用的私人日记产品。
- 让学习者理解每一段主要代码为什么存在，并能够自己修改。

因此，项目从原生网页技术开始，不直接使用大型框架。复杂功能只有在基础版本稳定后才加入。

## 2. 技术路线

### 第一阶段：原生网页

使用：HTML、CSS、JavaScript。

完成：

- 日记首页布局。
- 新建和编辑日记。
- 日记列表和详情。
- 删除和搜索。
- 使用 localStorage 保存数据。
- 手机和电脑自适应布局。

为什么先这样做：HTML、CSS、JavaScript 是所有网页框架的基础。先理解它们，后面学习 React 或 Vue 才不会只会复制代码。

### 第二阶段：自己的后端

使用：Node.js、Express、SQLite。

完成：

- 账号注册和密码登录。
- 密码哈希保存。
- 日记的增删改查接口。
- 登录状态和访问令牌。
- 输入验证与基础错误处理。

为什么选择 SQLite：它不需要单独安装数据库服务，适合学习数据表、查询和后端接口。产品上线前再学习迁移到 PostgreSQL。

### 第三阶段：离线与安装

使用：PWA、Service Worker、IndexedDB。

完成：

- 安装到手机桌面。
- 无网络时继续写作。
- 恢复网络后同步数据。
- 新版本自动更新提示。

### 第四阶段：移动应用

使用：Capacitor。

完成：

- 将现有网页封装成 Android 和 iOS 应用。
- 接入相册、通知和生物识别。
- 保持网页和手机端共用核心代码。

## 4. 第一版产品设计

第一版只保留五项核心功能：

1. 写一篇日记。
2. 自动记录日期和时间。
3. 查看以前的日记。
4. 搜索日记。
5. 删除日记。

第一版暂时不做：图片上传、富文本、多端同步、提醒、复杂动画、第三方登录。这些功能会在基础代码稳定后逐个加入。

## 5. 第一阶段文件结构

```text
日记本设计/
├─ index.html       网页的内容和结构
├─ styles.css       网页的外观和布局
├─ app.js           网页的交互和数据逻辑
├─ README.md        项目入口说明
└─ docs/            学习课程与设计记录
```

前三个文件分别回答三个问题：

- 页面上有什么？看 `index.html`。
- 页面长什么样？看 `styles.css`。
- 点击以后发生什么？看 `app.js`。

## 6. 教学规则

- 每一课最多引入三个新概念。
- 每段代码先解释作用，再亲手输入。
- 每一课提供语法规则、关键字表、常见错误和检查表。
- 为 HTML、CSS、JavaScript、Node.js 和 SQL 分别提供长期速查手册。
- 不直接复制大型成品代码。
- 不理解的语法先用最小例子验证。
- 每课结束时页面必须能够正常运行。
- 功能完成后再重构，不提前追求复杂架构。

## 7. 阶段验收

### 原生网页阶段完成标准

- 能解释 HTML、CSS、JavaScript 各自负责什么。
- 能独立修改标题、颜色、布局和按钮行为。
- 能读懂日记对象与日记数组。
- 能新增、编辑、搜索和删除本地日记。
- 刷新页面后数据仍然存在。

### 后端阶段完成标准

- 能解释浏览器、API 和数据库之间的关系。
- 能自己增加一个 API 路由。
- 能使用 SQL 查询自己的日记。
- 能解释为什么不能保存明文密码。

### 移动端阶段完成标准

- 网页可以安装并在断网时打开。
- Android 和 iOS 共用主要页面与业务逻辑。
- 能独立修改一个移动端功能并重新构建。
