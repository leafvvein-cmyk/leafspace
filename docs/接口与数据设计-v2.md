版本：2026-09-09 · 状态：已实现接口的设计基线与后续扩展契约。F01–F24 的实际覆盖范围和仍需原生、生产环境验证的边界，以 [开发进度与验收台账](开发进度.md) 为准；标注“保留”或“尚未实现”的接口仍只是设计约定。

配套文件：[产品设计方案](产品设计方案-v2.md)、[页面与导航设计](页面与导航设计-v2.md)。正式实现时，将字段约束放入 `packages/contracts` 的共享 schema，并生成 OpenAPI；不要分别在两端手写不同规则。

## 1. 先理解这几个词

| 名词 | 在本项目中的意思 |
| --- | --- |
| API / 接口 | 页面向服务器请求数据或提交操作的约定 |
| GET / POST / PUT / PATCH / DELETE | 分别用于读取、提交操作或创建、完整替换、局部修改、删除；由下文明确具体行为 |
| JSON | 前后端传递对象和数组的文本格式，不是数据库 |
| ID | 一条数据的稳定标识；日记使用客户端可生成的 UUID，便于离线创建 |
| revision | 服务器维护的数据版本号，用来发现两台设备同时编辑 |
| mutation | 一次已经固定内容的写入操作；重试时内容和 mutationId 都不能变化 |
| cursor | 分页或同步的位置凭据，只能使用服务器返回的值 |
| 事务 | 几个数据库修改一起成功或一起撤销，避免“日记已改但同步日志没写” |
| 幂等 | 相同操作重发不会重复生效；不是把两次不同编辑当成同一次 |
| reauth | 敏感操作前再次验证当前密码，不是手机验证码 |

## 2. 通用约定

- API 根路径 `/api/v1`；正式环境仅 HTTPS。Web 与 API 同源，手机配置明确的 HTTPS API 地址。
- JSON 请求为 `Content-Type: application/json`；浏览器/原生请求均可在 JSON 正文传中文。
- `Authorization: Bearer <accessToken>` 只放 ASCII 编码令牌。不要把中文昵称、日记正文、JSON 对象放入自定义 Header，这可以避免此前的非 ISO-8859-1 Header 错误。
- UTC 时间戳采用 ISO 8601，如 `2026-09-08T10:30:00.000Z`；日记日期另用 `2026-09-08`，时区为 `Asia/Shanghai` 等 IANA 名称。
- UUID 为字符串；revision 和同步序号在 JSON 中均用十进制字符串（如 `"7"`），避免数据库 bigint 超出 JavaScript 安全整数范围。
- 所有受保护查询先确定当前用户；目标不属于当前用户时统一 404，不暴露存在性。请求里的 `userId` 不能决定数据所有权。
- 列表默认 50 项、最大 100 项；游标绑定用户、排序和过滤条件，不允许拿一个筛选条件的游标用于另一个条件。
- 请求 ID 由服务器生成或验证。日志不记密码、恢复码、访问/刷新令牌、签名 URL、日记正文或完整搜索 URL；网关也需脱敏。
- 身份、日记、搜索、快照和导出接口返回 `Cache-Control: no-store`，不走公共 CDN 缓存。Service Worker 只缓存版本化静态外壳，不缓存 `/api/v1` 响应；离线私人数据由按账号隔离的本地库管理。图片二进制按需存入该账号缓存，不把签名 URL 当永久资源 ID。
- 除明确返回文件或 204 的接口外，采用以下封装。接口版本不等于正文 schemaVersion，两者分别演进。

成功示例：

```json
{
  "data": {
    "items": [],
    "nextCursor": null,
    "hasMore": false
  },
  "meta": { "requestId": "req_example" }
}
```

失败示例：

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "请检查输入内容",
    "fields": { "password": "密码至少需要 12 个字符" }
  },
  "meta": { "requestId": "req_example" }
}
```

| HTTP 状态 | 使用场景 |
| --- | --- |
| 200 / 201 / 202 / 204 | 成功 / 创建成功 / 后台任务已接受 / 成功且无响应体 |
| 400 / 422 | 请求结构或游标不正确 / 字段、正文 schema、业务输入不合法 |
| 401 / 403 / 404 | 身份失效 / 需再次验证或 CSRF 不通过 / 数据不存在或不属于本账号 |
| 409 | 版本、每日唯一性、幂等键或名称冲突 |
| 410 | 同步游标/快照已过期，或本人的目标 ID 已永久删除 |
| 413 / 429 / 503 | 内容过大 / 频率限制 / 服务暂不可用 |

429 附 `Retry-After` 秒数。客户端只对超时、可恢复的 5xx/429 自动退避重试；401 先恢复会话，409 转人工处理，不能统一无限重试。

## 3. 账号、会话和安全接口

### 3.1 注册与密码规则

账号为 3–32 个 ASCII 字符，首位字母或数字，其余允许字母、数字、点、下划线、短横线；去除首尾空白后转小写作为唯一键。昵称独立，允许中文，不能拿昵称当 Header 或数据库身份。

新账号密码为 12–128 个 Unicode 码点，并限制 UTF-8 编码不超过 512 字节；不 trim、不截断、不做隐式 Unicode 归一化。支持粘贴、密码管理器和显示密码，无强制大小写混合。确认密码只在页面比较，不入库。本规则用于新系统，若日后发现旧账号，迁移策略另定，不能直接让旧账号全部失效。

服务端用 Argon2id 存哈希，不存明文或可逆密码。参数先以 OWASP 基线评估，再在目标服务器压测；参数及盐编码进哈希，便于升级。[OWASP 密码存储说明](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

没有短信、手机号验证、Apple 登录、社交登录接口。恢复方式为一次性恢复码，仍然是账号密码登录体系；不持有密码也没有恢复码时，不承诺可以找回账户。

### 3.2 Web 与 App 的认证传输

| 项目 | Web / PWA | Android / iOS App |
| --- | --- | --- |
| accessToken | 仅页面内存，默认 15 分钟 | 仅进程内存，默认 15 分钟 |
| refreshToken | `HttpOnly; Secure; SameSite=Strict` Cookie，不返回 JS | 响应体返回一次，写入 Keychain/Keystore 保护的适配器 |
| 刷新方式 | Cookie + CSRF Token | JSON 中提交 refreshToken，返回轮换后的 token |
| 跨站保护 | 校验 Origin、CSRF Token、凭据策略 | 不依赖浏览器 Cookie；CORS 不是身份验证 |
| 本地存储禁区 | 不把 token 放 localStorage / IndexedDB | 不把 refreshToken 放普通 Preferences / 明文 SQLite |

服务器保存高熵不透明 refreshToken 的哈希与会话状态，默认 30 天绝对有效期；轮换不无限延长原会话期限。刷新轮换在事务中完成，已用 token 再出现则撤销该会话的 token family。客户端使用单飞请求，Web 多标签页协调唯一刷新者；刷新响应丢失而无法恢复时要求重新登录，不反复重放旧 token。

accessToken 包含用户 ID、会话 ID、过期时间等必要字段；验证签名、issuer、audience、时效后，每个 API 仍检查用户/会话是否有效，确保远程退出立即阻止后续请求。设备自报名称仅供展示，不是可信硬件标识。

| 方法与路径 | 请求要点 | 响应 / 行为 |
| --- | --- | --- |
| `GET /auth/csrf` | Web 获取；不缓存 | 预登录会话绑定的 ASCII csrfToken；账号切换/登录后更新 |
| `POST /auth/register` | username、password、device；Web CSRF | 201；user、session、accessToken；设置刷新 Cookie |
| `POST /auth/login` | 同上 | 200；同上；账号/密码错误统一 AUTH_FAILED |
| `POST /auth/refresh` | Cookie + `X-CSRF-Token` | 新 accessToken 与轮换刷新 Cookie |
| `POST /auth/native/register` | username、password、device | 201；另返回 refreshToken、refreshExpiresAt |
| `POST /auth/native/login` | 同上 | 200；同上，不设置 Web 刷新 Cookie |
| `POST /auth/native/refresh` | refreshToken | 新 accessToken 与新 refreshToken |
| `POST /auth/logout` | 当前身份；Web 同时清刷新 Cookie | 204；撤销当前会话；本地稿按退出流程先处理 |
| `GET /me` | 当前身份 | id、username、displayName、timezone、recoveryCodeConfigured、revision；profile 增量实体采用同名 revision |
| `PATCH /me` | displayName、timezone、baseRevision | 资料新 revision；账号名首版不可改 |
| `POST /auth/reauth` | password、scope、targetId（单目标）或 targetIds（批量） | reauthToken、expiresAt，默认 5 分钟、绑定用户/会话/具体操作；批量最多 20 个 ID，服务端排序去重后生成集合摘要 |
| `POST /security/password` | newPassword、reauthToken、requestId | 修改哈希并撤销所有会话；页面重新登录 |
| `POST /security/recovery-code` | reauthToken、requestId | 只显示一次的新 recoveryCode；旧码失效 |
| `POST /auth/password-reset` | username、recoveryCode、newPassword | 成功后消耗恢复码、撤销所有会话；无自动登录 |
| `GET /sessions` | 当前身份 | id、设备名、platform、createdAt、lastSeenAt、isCurrent |
| `DELETE /sessions/:id` | 当前身份、有效再次验证凭据 | 撤销指定会话；多次撤销无额外副作用 |
| `POST /sessions/revoke-others` | reauthToken、requestId | 撤销除当前会话外全部会话 |

Cookie 型状态变更均校验 CSRF；Bearer API 不从 Cookie 自动补 access 身份。HTTP DELETE 不依赖请求体，再验证凭据使用 ASCII `X-Reauth-Token`。scope 使用固定枚举，例如 `change_password`、`rotate_recovery_code`、`revoke_session`、`purge_entry`、`purge_entries`、`delete_account`；`targetId` 或 `targetIds` 必须与实际对象/完整集合一致，两字段互斥，不能通过缩减或扩展选中集合复用授权。

reauthToken 只在内存中短暂保存，服务端存哈希，一次消费；修改密码、撤销会话、消费 reauth 等属于同一业务事务。支持幂等 requestId 的操作先核验当前身份/作用域，再查本用户操作回执；不得通过回执绕过注销或会话撤销。敏感结果不存明文回执：恢复码生成响应丢失时，重新验证并重新生成，新码使之前的码失效。

注册后的第一枚恢复码可使用注册会话 5 分钟内的单次 onboarding 授权；超时或重新生成需再次输密码。恢复码由密码学随机源生成至少 128 位随机量，服务器只保存带服务端密钥的摘要，展示时允许分组便于抄写；找回提交的无效账号/无效码统一失败，不用“是否存在账号”区别提示。

频率限制初值：按账号和可信来源 IP 双维度限制登录/找回尝试，采用逐步退避和临时限制，不永久锁死账号。注册、恢复码、图片和导出另设用户配额；上线前压测与攻击模拟后固定阈值。日志和错误不回显密钥。

Web 登录请求示例（虚构账号）：

```json
{
  "username": "diary_demo",
  "password": "A-demo-passphrase-2026!",
  "device": { "installationId": "378c52ab-02bf-4f7e-a78d-a17a8ff9bc2d", "platform": "web", "name": "我的电脑" }
}
```

Web 响应 `data` 含 `user`、`session`、`accessToken`、`accessExpiresAt`，不含 refreshToken。密码示例不能写入真实种子账号或生产配置。

## 4. 日记数据契约

### 4.1 Entry 字段

| 字段 | 类型与约束 | 说明 |
| --- | --- | --- |
| id | UUID | 客户端预先生成，永久删除后不可重用 |
| kind | daily / moment | 每日一页 / 随记 |
| entryDate | YYYY-MM-DD | 业务归属日期，不因设备时区变化重算 |
| timezone | IANA 时区 | 创建/明确改日期时记录 |
| occurredAt | UTC 时间或 null | 随记必填；daily 可为 null |
| title | 字符串，0–120 个码点 | 无标题由 UI 展示日期，不伪造用户标题 |
| contentSchemaVersion | 整数，首版 1 | 结构化正文的独立版本 |
| content | Tiptap JSON doc | 白名单节点和 marks；不接受任意 HTML |
| plainText | 服务器派生，只读 | 搜索和摘要来源；不信任客户端提交的值 |
| mood | 整数 1–5 或 null | 依次为很低落、低落、平静、愉快、很开心；不是医疗量表 |
| tagIds | UUID 数组，只读标准化结果 | 写入时使用下面的 tags 输入结构 |
| revision | 十进制字符串 | 服务器维护；创建前 baseRevision 为 `"0"` |
| createdAt / updatedAt | UTC，只读 | 不用于冲突覆盖决策 |
| deletedAt / purgeAfter | UTC 或 null，只读 | 回收站状态与服务器清理时间 |

写入 `tags` 为最多 10 项的数组，每项仅为 `{ "id": "…" }` 或 `{ "name": "生活" }`。名字先去首尾空白、NFKC 规范化和小写折叠生成唯一比较键，展示保留合法原名；单名 1–24 个码点。服务端按用户范围解析/复用 ID，返回 canonical `tagIds`；离线添加的新标签无需先联网建 ID。已删除的 tag ID 返回 TAG_NOT_FOUND，不静默重建。

正文首版允许 doc、paragraph、text、heading（1–3）、bulletList、orderedList、listItem、taskList、taskItem、blockquote、horizontalRule、hardBreak、image；marks 为 bold、italic、underline。首版不开放原始 HTML、任意 embed 或任意外部图片 URL，外部链接粘贴先视为文本。图片节点使用 `assetId`、alt、caption 等受控属性，不存签名 URL 或 Base64。

初始限额：正文 JSON 最大 1 MiB、最大深度 20、最大节点数 10,000、正文纯文本最多 100,000 码点、每篇最多 20 张图；批次最大 4 MiB。API 校验后再提取纯文本，前端安全构建 DOM，不将服务端字符串直接插入 innerHTML。标题/有效正文/图片至少有一项非空，纯空白不算内容。

daily 同账号同日期只允许一条未删除记录。随记没有每日数量唯一约束。改类型、改日期或恢复都检查唯一性，返回现有 daily 的 ID 供当前用户处理。

### 4.2 查询、在线写入与管理接口

| 方法与路径 | 参数或请求 | 返回 / 要点 |
| --- | --- | --- |
| `GET /entries` | date 或 from/to、kind、mood、tagId、q、state、cursor、limit | 摘要列表、nextCursor、hasMore；state 默认 active，可选 trash |
| `GET /entries/:id` | 当前身份 | 完整 Entry；回收站内容只读 |
| `POST /entries` | mutationId、baseRevision=`"0"`、entryId、payload | 201；在线创建，同一 mutation 服务 |
| `PUT /entries/:id` | mutationId、baseRevision、payload | 200；完整可写快照替换，不是缺字段补空 |
| `POST /entries/:id/trash` | mutationId、baseRevision | 软删除，设 deletedAt 和 30 天后的 purgeAfter |
| `POST /entries/:id/restore` | mutationId、baseRevision、可选 kind/entryDate/timezone/occurredAt | 恢复或明确改为随记/其他日期后恢复 |
| `POST /entries/:id/purge` | requestId、baseRevision、reauthToken | 在线永久删除；返回 tombstone，附件按引用清理 |
| `POST /entries/purge-batch` | requestId、items=[{entryId, baseRevision}]、reauthToken | 最多 20 篇；reauth scope=purge_entries 且绑定排序后的 ID 集合摘要；整批事务，全部成功或全部回滚 |
| `GET /calendar` | month=YYYY-MM | 每天 dailyId、momentCount、totalCount、mood |
| `GET /stats` | 可选 from/to | 未删除的篇数、记录天数；本地待同步稿另行叠加并标注 |
| `GET /tags` | cursor、limit | id、name、revision、activeEntryCount |
| `POST /tags` | name、requestId | 已有规范化同名返回该标签；没有则创建 |
| `PATCH /tags/:id` | name、baseRevision、requestId | 改名；撞名返回 TAG_NAME_CONFLICT，用户确认后走 merge |
| `DELETE /tags/:id` | baseRevision 查询参数、`Idempotency-Key` Header | 删除标签及关系，不删除日记 |
| `POST /tags/:id/merge` | targetTagId、baseRevision、targetRevision、requestId | source 合并到 target；去重关系并删除 source |

`GET /entries` 的 q 为最多 100 个码点的字面查询，匹配标题、服务端 plainText 或所关联标签名；转义 LIKE 通配符并使用 SQL 参数，`%` 不被解释为任意字符。日期区间包含首尾；date 与 from/to 不可同时使用。关键词不进入前端地址栏，API 网关不记录原始查询字符串。

列表按 `entryDate DESC, sortAt DESC, id DESC`，其中 `sortAt=occurredAt ?? createdAt`；游标包含最后一个排序元组。普通列表在并发编辑下是实时视图，客户端按 ID 去重、刷新能重新排序，不承诺长期冻结的完整快照；同步和导出需要稳定快照，不能用此列表分页代替。

日历仅统计 active；当天 mood 优先 daily 的非空值，否则取最新一个有心情的 moment，均无则 null，不将不同心情擅自平均。GET entries/trash 与日历、stats 使用同一账号/日期规则。

在线日记创建/编辑/软删除/恢复接口是 `POST /sync/mutations` 业务服务的薄封装，不允许实现两套不同的校验和版本更新逻辑。批量软删除/恢复使用 mutations 中明确列出的 ID，结果逐项展示。永久批量删除先展示选中 ID 和数量，再通过 purge-batch 在一个事务中验证全部目标、一次消费绑定该集合的 reauth 并执行全部删除；任何冲突整批回滚，不暗中扩展为所有搜索结果。单篇/批量永久删除共用同一 purge 业务服务；静态 purge-batch 路由必须在 `:id` 路由之前注册。

创建 daily 的 `payload` 示例：

```json
{
  "kind": "daily",
  "entryDate": "2026-09-08",
  "timezone": "Asia/Shanghai",
  "occurredAt": null,
  "title": "普通而值得记录的一天",
  "contentSchemaVersion": 1,
  "content": {
    "type": "doc",
    "content": [
      { "type": "paragraph", "content": [{ "type": "text", "text": "今天开始认真写日记。" }] }
    ]
  },
  "mood": 4,
  "tags": [{ "name": "生活" }]
}
```

## 5. 离线保存与同步协议

### 5.1 本地库职责

每账号一个隔离的数据空间，包括 `cloudEntries`（已确认云端镜像）、`drafts`（本机最新编辑稿）、`outbox`（固定的待发送操作）、`localAssets`、`conflicts`、`syncState`。本地事务负责同时写草稿与待提交标记；编辑器从本机稿优先展示。

每次编辑增加本地 generation。未发出的快照可合并减少请求；一旦发送，mutationId 和 payload 固定。收到旧 generation 的确认只能结算该操作回执，不能用它覆盖用户后来打的字。云端镜像 revision 必须单调递增：晚到的 HTTP 确认若低于已应用增量版本，不得回退镜像。同一篇同时最多一个写请求在途，不同篇可有限并发。

每份本机稿同时记录其真实派生自的云端 baseRevision/baseContent。只有镜像仍是该基线或本机前一次已确认的写入时，才推进下一次修改基线；有未提交稿而云端出现其他来源的改动时先进入冲突比较。禁止把旧正文仅换成最新 baseRevision 后重新提交，这会绕过冲突检测。用户确认合并后，合并稿才以实际比较过的云端版本作为新基线。

数据库和图像文件通过适配器隔离 Web/Native。移动文件写入先暂存，再以本地事务记录可恢复的状态，启动时收拾已登记的临时文件；不能声称 SQLite 事务能原子提交整个文件系统。

### 5.2 上传端点

`POST /sync/mutations`，每批最多 20 项和 4 MiB，顺序处理，每项独立事务；同篇前一项失败后，依赖它的后续项返回 DEPENDENCY_BLOCKED。传输层成功返回 200，业务结果看每项 status；网络层失败仍用标准错误封装。

支持三种日记操作：

- `upsert`：baseRevision=`"0"` 是创建；其他 revision 是完整快照更新，只可写 active。
- `trash`：版本匹配后进入回收站；已删除状态在正确版本下返回无变更确认。
- `restore`：版本匹配后恢复，payload 可明确变更日期/类型；daily 冲突时不改旧内容。

示例请求：

```json
{
  "mutations": [
    {
      "mutationId": "8b1c4f94-6a8b-47ed-8d35-1850574a3345",
      "entryId": "8c8666be-38e6-46f5-9ac1-6c24615e4f95",
      "baseRevision": "7",
      "operation": "trash",
      "payload": {}
    }
  ]
}
```

成功时每项含 `mutationId`、`status: "applied"`、完整 canonical Entry、`changeSeq`；相同请求重放 `status: "replayed"`，返回原结果，不再次写库。冲突示例：

```json
{
  "data": {
    "results": [
      {
        "mutationId": "8b1c4f94-6a8b-47ed-8d35-1850574a3345",
        "status": "conflict",
        "error": {
          "code": "REVISION_CONFLICT",
          "message": "这篇日记已在其他设备更新",
          "details": {
            "entryId": "8c8666be-38e6-46f5-9ac1-6c24615e4f95",
            "currentRevision": "8"
          }
        }
      }
    ]
  },
  "meta": { "requestId": "req_example" }
}
```

冲突响应可携带本账号的 currentEntry，也可让客户端 GET 最新版；同步中心总是保留本机快照、baseRevision、远端最新版本和原因。新合并或另存是新 mutationId，不能修改已提交 mutation 的 payload 再重用 ID。

### 5.3 事务、序号与去重

服务器写入流程：确认身份 → 锁定该用户 sync_state 行 → 查 `(userId, mutationId)` 回执并比较规范化请求哈希 → 校验对象所有权、revision、每日唯一性、标签和附件 → 写日记/关系 → revision 增加 → 分配该用户下一 changeSeq 并写变更事件 → 写回执 → 一起提交。

同一用户的变更序号通过锁定行串行提交，不能只用全局自增 ID 后凭大小分页：较小序号事务晚提交可能造成客户端越过它。所有写入口，包括标签管理、偏好、清理任务，都遵循相同提交顺序。普通规模下先采用每用户串行写，压测后再优化。

回执保留 180 天，存规范化请求哈希、结果/错误摘要、返回版本，不存密码/恢复码。相同 mutationId 不同请求返回 IDEMPOTENCY_KEY_REUSED。可确定的版本/校验冲突写回执；临时基础设施故障回滚，不把它永久记为成功或确定失败。对超过回执期限的旧队列，先重新拉取并人工比对，禁止自动当新操作重放；过期时间策略需由 `meta` 告知客户端。

永久删除保留不含正文的 tombstone 和不可重用 ID，直到账号生命周期结束；以后旧客户端写同 ID 返回 ENTRY_PURGED。软删除、改日期、永久删除以及标签关系变化都产生同步事件。

### 5.4 首次同步、增量与游标过期

| 方法与路径 | 用途 | 返回 |
| --- | --- | --- |
| `POST /sync/snapshots` | 首次登录或过期游标重建，requestId 幂等 | 202；snapshotId、status |
| `GET /sync/snapshots/:id` | 查询准备状态 | queued / running / ready / failed / expired |
| `GET /sync/snapshots/:id/pages` | pageCursor、limit，读取冻结内容 | records、nextPageCursor、hasMore、最终 baselineCursor |
| `GET /sync/changes` | cursor、limit | events、nextCursor、hasMore、serverTime |

worker 在数据库一致性快照内生成冻结的当前用户数据集和同一快照对应的 baseline 序号，包括 active/trash entries、标签、带 revision 的 profile、账号级设置和附件元数据；分页读已物化的快照，不跨多个 HTTP 请求持有数据库事务。状态 ready 后默认保留 30 分钟，读取按 ID 和过期时间鉴权，失败可重建。首次仅下载图片元数据，二进制按需获取。

客户端先暂存全部分页，完成校验后原子切换云端镜像和 baselineCursor，再开始增量。重建前将 drafts/outbox/conflicts/未上传图片隔离保护，不能“清库重新登录”顺带删除它们。复制来的旧云端镜像可替换，本机稿不能替换。

增量事件示意（events 可以包含多个实体，客户端按一个事件事务应用）：

```json
{
  "data": {
    "events": [
      {
        "seq": "1042",
        "type": "transaction",
        "changes": [
          { "entity": "entry", "id": "8c8666be-38e6-46f5-9ac1-6c24615e4f95", "action": "purge", "revision": "9" }
        ]
      }
    ],
    "nextCursor": "opaque_server_cursor",
    "hasMore": false,
    "serverTime": "2026-09-08T10:30:00.000Z"
  },
  "meta": { "requestId": "req_example" }
}
```

`upsert` change 携带 canonical 实体，`purge` 只含身份、revision、删除时间；同事务标签/关系变化和 entry 变化一起应用。大规模标签合并可超过单页上限时返回受控 `resnapshot_required` 事件，事务提交完后客户端保护稿件并拉新快照，不能截断一半的事务。配置事件体积上限并测试此分支。

cursor 是绑定用户、数据世代、最后序号和本轮固定 high-water 的不透明签名值；一轮分页固定上界，避免新写入造成一直追不完。hasMore=false 才开始下一轮。重复下载事件可按 revision/seq 安全忽略；只有本地应用事务成功才能推进 cursor。

变更日志至少保留 90 天；过旧 cursor 返回 410 SYNC_CURSOR_EXPIRED，执行上述保护稿件+快照重建流程。后台修复/数据库恢复若可能回退序号，必须更换数据世代并强制重新快照，不让旧游标默默漏数据。

### 5.5 冲突矩阵

| 冲突 | 服务器响应 | 客户端处理 |
| --- | --- | --- |
| 两端改同篇 | REVISION_CONFLICT | 本机/云端比较，保留云端、另存随记、手工合并 |
| 两端建同日 daily | DAILY_ALREADY_EXISTS + existingEntryId | 保留后到稿，合并或另存随记，不自动覆盖 |
| 本机编辑、远端软删除 | ENTRY_TRASHED + 当前 revision | 只读查看，可明确恢复后再合并，或另存 |
| 本机编辑、远端永久删除 | ENTRY_PURGED | 旧 ID 不复活；本机内容可另存新 ID |
| 恢复 daily 撞同日 | DAILY_ALREADY_EXISTS | 用户改日期/类型后新请求；原稿仍在回收站 |
| 标签已被删除/合并 | TAG_NOT_FOUND 或 canonical 映射 | 提示/刷新标签，不擅自复活已删标签 |
| 同步期间会话撤销 | SESSION_REVOKED | 暂停队列、锁定，重新登录同账号，不丢稿 |

## 6. 图片与文件接口

| 方法与路径 | 请求 | 返回 / 行为 |
| --- | --- | --- |
| `POST /assets/uploads` | assetId、requestId、mimeType、size、sha256 | 私有上传 URL、严格受限上传 headers、expiresAt |
| `POST /assets/:id/upload-credentials` | requestId、原文件 sha256 和 size | pending 状态下重新鉴权后补发未过期凭据，不改变文件身份；ready 不允许覆盖 |
| `POST /assets/:id/complete` | requestId | 202；验证实际文件并生成缩略图任务 |
| `GET /assets/:id` | 当前身份 | pending / processing / ready / failed、尺寸、失败原因 |
| `POST /assets/:id/read-url` | variant=thumbnail/original | 当前用户可读的短期 URL，默认有效 5 分钟 |
| `DELETE /assets/:id` | 仅未引用资源；Idempotency-Key | 放弃上传/删除孤立资源；正在引用返回 ASSET_IN_USE |

客户端先压缩并移除定位等 EXIF 元数据；首版上传白名单 JPEG/PNG/WebP，单张上限 10 MiB、最大解码像素 25MP。移动端 HEIC 需转换为 JPEG 或明确提示不支持，M0 验证；SVG 和任意 HTML 不作为图片接收。服务器独立验证真实类型、大小、解码限制和校验和，重编码后生成 ready 版本，不信任客户端声明。

上传原件写隔离对象 key，校验后生成不可覆盖的最终私有 key；仍有效的上传 URL 不能覆盖已通过校验的最终文件。桶不公开，路径不含账号名/中文标题；返回 URL 不是永久权限。预签名链接已发出后难以即时撤回，远程退出或注销不能承诺取消其剩余 5 分钟访问期；更强需求改为每次经 API 流式鉴权。

本地正文保留所有图片占位；服务器 Entry 只引用本账号 ready 的 asset。为了文字可先同步，从本机稿生成暂不含待上传图的云端快照；本机仍保留完整稿与图片队列，显示“文字已同步，图片待上传”。图 ready 后，补图操作以文字阶段实际确认的 revision 为基线；如果之后只有本机已经确认的编辑，可沿本机链推进，若远端有改动则先比较/合并或报冲突，禁止仅换成远端最新版本号提交旧的完整正文。不能用先前文字确认清掉本机图片。只有图片的空标题稿需等至少一张图 ready 后才创建云端 Entry。

上传 URL 过期时，不重复请求已缓存的旧初始化回执，改用 upload-credentials 并生成新的 requestId；服务器核验资源仍属于当前用户、状态仍 pending、文件摘要与大小未变后签发新链接。孤立上传记录已清理返回 ASSET_UPLOAD_EXPIRED，客户端生成新 assetId、更新本机图片引用并重传，不复用不可用 ID。仍在 processing 时查询进度，不重新覆盖源文件。

正文删除图片只移除关联，不立即删原件；服务端以实际引用计数/关联查询决定清理，草稿上传未关联的资源至少保留 7 天，客户端重连发现已过期则从本地重传。任务失败可重试；回收站中的引用在保留期内仍有效，永久删除最后引用后清理所有派生版本。

图片按需下载，所以“可以离线写作”不等于“所有历史原图已离线”。已查看缓存与用户明确下载的内容可离线读；未缓存图片显示联网下载提示。未上传文件始终不参与自动缓存淘汰。

### 7.1 设置与本机安全

资料与外观可离线修改并加入各自的版本化本地队列；联网分别调用 PATCH /me 或 PATCH /settings，不冒充 Entry mutation。服务器将它们写入同一用户变更流。设备锁的 PIN、盐、密钥、生物识别状态只在本机安全适配器，不上传到 preferences API。

设备提醒偏好可本地立即调整，待在线保存元数据；排程依赖当前系统权限、时区和成功回调。新设备默认关闭提醒，不从其他设备继承开启状态。操作系统权限与偏好各自展示，重新安装后不能仅凭服务端 `enabled` 显示“已设置成功”。

### 7.2 导出

单篇 Markdown 可本地即时生成；Web PDF 使用独立打印样式，手机需验证原生打印/文件分享。云端批量导出取任务开始时的一致性快照，记录 snapshotAt；避免一边导出一边被编辑造成正文和附件混搭。任务使用数据库队列、lease/心跳、有限重试和幂等输出路径；API 重启不丢任务。任务期间所需的 ready 附件以短期引用租约保护，避免普通未引用资源清理使导出缺图；永久删除/账户注销优先使任务失效并撤销租约，不为导出阻止隐私删除。

JSON ZIP 含 `manifest.json`、`entries.json`、`tags.json`、`assets/` 和校验和；manifest 提供 exportSchemaVersion、生成时间、业务快照时间、条目数及附件清单。Markdown ZIP 使用无冲突、路径安全的文件名，并使用相对附件链接，不把用户标题直接拼成任意磁盘路径。默认不含回收站、密码、恢复码、token；是否包含回收站需作为独立明确选项，首版不提供该选项。

面向用户的通用 ZIP 导入器不在默认范围；数据库+对象存储备份恢复属于运维。云端导出、单篇文件和本地未同步稿导出都需要提示导出文件本身是明文，由用户保管。

### 7.3 注销与备份恢复

注销事务先将用户状态设为 deleting、撤销全部会话、创建持久清理任务并生成只读回执。之后立即拒绝业务 API；worker 清理主库正文、标签、附件、导出及衍生数据，失败重试/告警。回执 token 仅可看清理状态，默认保留至任务完成后 30 天，不可恢复身份。

设计目标为在线主数据 7 天内清理完成，备份按 30 天滚动保留自然淘汰；这些是待落实的运维策略，不是当前保证。隐私页要同时说明主数据、备份、短期下载链接和离线设备副本的边界。备份恢复后在开放业务流量前应用删除台账，重新检查会话撤销状态并变更同步世代，避免让已经注销的数据重新上线。

### 7.4 待办与动作接口（扩展契约）

| 接口 | 输入 | 结果与约束 |
| --- | --- | --- |
| `GET /tasks` | state、cursor、limit | 当前账号的任务摘要；账号绑定签名游标分页，不返回密码本数据；当前页面的关键词和优先级筛选在已下载本机任务中完成 |
| `POST /tasks` | taskId、requestId、payload | 幂等创建；payload 含标题、备注、截止时间及时区、重复规则、提醒和子项 |
| `PATCH /tasks/:id` | baseRevision、requestId、patch | 版本匹配更新；离线冲突保留两份，不按设备时间覆盖 |
| `POST /tasks/:id/complete` | baseRevision、requestId | 幂等完成；重复任务的下一实例与完成操作同事务生成 |
| `POST /tasks/:id/reopen` | baseRevision、requestId | 重新打开，不倒退已生成的重复实例 |
| `DELETE /tasks/:id` | baseRevision、`Idempotency-Key` | 软删除并允许恢复；清理期限另定 |
| `GET /task-action-types` | 当前身份 | 返回当前服务端允许的站内目标、HTTPS 规则和已登记外部 App 能力；当前外部 App 列表为空 |
| `PUT /tasks/:id/actions` | baseRevision、requestId、actions | 只保存通过白名单 schema 校验的动作；不接受脚本、命令或任意协议 |

执行动作是客户端能力，不提供“服务端远程打开 App”接口。当前站内页面和 HTTPS 动作可由页面编辑，使用独立幂等同步请求，执行前显示目标并要求确认；重复任务会复制动作但重新生成动作 ID。动作记录仅保存固定类型、公开目标标识和经 schema 校验的非敏感参数；企业微信具体动作在需求确定后增加版本化类型。iOS/Android 分别配置允许查询的 scheme/package，Web 仅在用户手势中尝试打开；所有平台失败时均不得修改任务完成状态。

原生 App 快捷动作使用 `type='external_app'`，`target` 只能是产品代码中共享白名单的稳定 ID；服务器与客户端均拒绝任意用户输入的 URL scheme、Android 包名或命令。动作目录为空时 `/task-action-types` 返回空 `externalApps`，页面不提供 App 动作编辑入口。登记动作时需同时明确平台目标和系统查询声明，执行前确认具体动作并检查目标 App 可用性，失败不改变待办状态。

重复规则按判别字段保存：每天为 `{frequency:'daily', interval}`；每周增加 `weekdays:[1..7]`；每月增加 `dayOfMonth:1..31`。旧的每周/每月记录缺少扩展字段时分别取原截止日期的当地星期和日期。下一次实例使用任务保存的 IANA 时区计算当地日历，跨夏令时保持当地钟点；每月 29–31 日遇到短月取该月最后一天，但规则本身不降级，后续长月仍恢复原日期。

待办提醒不经过服务端推送：网页只在页面打开期间检查；Android/iOS 使用本地通知插件。客户端以 taskId 和提醒时刻去重，任务编辑、完成、删除、同步或冲突选择后重新取消/安排；系统通知使用通用正文，不包含标题、备注或子项。原生一次只保留未来最近 50 项，未获权限时保存待办但明确显示提醒未生效。

### 7.5 密码本接口（扩展契约）

| 接口 | 输入 | 结果与约束 |
| --- | --- | --- |
| `PUT /vault/config` | requestId、baseRevision、kdf、salt、wrappedKey、wrapNonce、cryptoVersion；可选完整 recoveryWrappedKey、recoveryNonce、recoveryVersion 三元组 | 首次创建或经严格轮换流程更新；只接受版本化算法参数和密文字节；旧客户端未提交恢复字段时保留服务端已有恢复包装 |
| `GET /vault/config` | 当前身份 | 返回客户端解锁所需的公开参数和包装密钥，不返回任何明文 |
| `GET /vault/items` | cursor、limit | 按更新时间和 opaque itemId 使用账号绑定签名游标分页，返回 ciphertext、nonce、revision、updatedAt/deletedAt；无服务端明文搜索 |
| `PUT /vault/items/:id` | requestId、baseRevision、ciphertext、nonce、cryptoVersion | 幂等写入一个 App/网站账号的完整加密载荷；版本冲突返回双方密文，由已解锁客户端处理 |
| `DELETE /vault/items/:id` | `Idempotency-Key` 请求头、baseRevision 查询参数 | 写入不含明文的删除标记并参与同步 |
| `POST /vault/key-rotations` | requestId、baseConfigRevision、itemCount、新包装参数和完整恢复包装 | 创建 24 小时有效的分阶段数据密钥轮换；开始时核对配置版本和账号记录总数，不接受缺少新恢复包装的请求 |
| `PUT /vault/key-rotations/:id/items` | requestId、最多 50 条 `{id,baseRevision,ciphertext,nonce,cryptoVersion}` | 幂等分批暂存使用新数据密钥生成的密文；服务端逐项核对当前版本，不改变正式密码本 |
| `POST /vault/key-rotations/:id/commit` | requestId | 锁定配置、全部账号记录和轮换任务；仅在记录集合、配置版本及每条版本完全匹配时，于同一数据库事务切换全部密文和包装参数 |

解密后的条目 schema 固定为 `{type, serviceName, username, password, loginUrl?, appIdentifier?, note?, tags[], favorite, otpSecret?, otpDigits?, otpPeriod?}`，其中 `type` 只能是 `app` 或 `website`；`otpSecret` 仅接受规范化 Base32，位数限定 6/8、周期限定 30/60 秒，并只在客户端用 HMAC-SHA1 按 RFC 6238 计算。`tags` 最多 20 项、每项最多 30 个字符，仅在客户端解密后用于搜索与筛选。旧密文缺少 `tags` 或 TOTP 字段时继续兼容。同一服务和账号不设服务端唯一约束。密码本接口拒绝服务端可读的服务名称、账号、密码、网址、App 标识、备注、标签、收藏、TOTP 密钥和搜索词。请求体、错误、审计、APM 与反向代理日志不得记录解密内容或密码学材料。普通账号恢复码和密码重置不解密保险库；密码本恢复仅在客户端使用一次性显示的 256 位恢复密钥解开独立 AES-GCM 包装，成功后换发恢复密钥并上传新的密文包装，服务器始终不能取得恢复密钥或数据密钥。

密码本独立备份是本机文件流程，不经过云端导出 API。格式只包含版本号、KDF/包装参数、opaque itemId、nonce 与 ciphertext；导出需再次输入当前保险库密码，导入只允许进入空保险库，并在任何写入前完成格式、重复 ID、密码和所有条目认证解密校验。导入后由本地事务一次写入配置、条目和待同步标记，不自动覆盖已有保险库。

## 8. 服务端数据表与约束

| 表 | 核心字段与约束 |
| --- | --- |
| users | id、username_normalized 唯一、display_name、password_hash、timezone、profile_revision、status |
| sessions | id、user_id、installation_id、platform、name、refresh_family、refresh_hash、expires_at、revoked_at |
| used_refresh_tokens | token_hash、session_id、used_at；用于轮换重放识别，清理遵守会话有效期 |
| recovery_codes | user_id、code_digest、created_at、consumed_at；每用户最多一枚可用码 |
| reauth_tokens | token_digest、user_id、session_id、scope、target_id/target_set_hash、expires_at、consumed_at |
| entries | id、user_id、kind、entry_date、timezone、occurred_at、title、content_schema_version、content、plain_text、mood、revision、sort_at、deleted_at、purge_after |
| tags / entry_tags | 用户内 normalized_name 唯一；关联表 (user_id, entry_id, tag_id) 唯一，复合外键确保三者同属用户 |
| assets / entry_assets | 上传状态、源/最终私有 key、mime、大小、hash、缩略图；正文引用关系由服务端解析建立 |
| sync_state | user_id 主键、generation、last_seq；写事务锁此行以确保用户内提交顺序 |
| sync_events | (user_id, seq) 唯一、changes、created_at；索引供增量读取，事件中的旧正文按保留策略清理 |
| mutation_receipts | (user_id, mutation_id) 唯一、request_hash、result、created_at、expires_at |
| entry_tombstones | (user_id, entry_id) 唯一、final_revision、purged_at；不保存正文 |
| user_settings / device_preferences | user_id + revision；后者再以 installation_id 分区，含提醒偏好不含本地 PIN |
| jobs | id、user_id、type、status、attempts、lease_until、next_run_at、result_ref、error_code |
| snapshots / snapshot_records | 用户、baseline_seq、generation、状态、TTL、冻结分页记录 |
| exports | 用户、job_id、snapshot_at、format、私有输出位置、状态、expires_at |
| account_deletions | 用户删除台账、回执摘要、阶段、失败原因；严格最小化个人信息 |
| tasks / task_items | 用户、标题/备注、截止时间及时区、优先级、重复规则、状态、revision；子项与任务同属用户 |
| task_actions | task_id、固定 action_type、版本化参数、排序；禁止任意可执行内容和敏感凭据 |
| vault_configs | user_id、KDF/算法版本、salt、wrapped_key、wrap_nonce、revision；不含保险库密码 |
| vault_items | user_id、opaque item_id、ciphertext、nonce、crypto_version、revision、deleted_at；服务端不可读明文字段 |

关键索引和事务约束：

1. `entries(user_id, entry_date)` 的部分唯一索引，条件 `kind='daily' AND deleted_at IS NULL`。
2. 时间线索引 `(user_id, entry_date DESC, sort_at DESC, id DESC)`；trash 清理用 purge_after 索引。
3. 标签关联双向索引；搜索按用户范围且 active 过滤，plain_text/title 的 pg_trgm 索引只作为性能优化，不改变字面查询含义。
4. tags 改名、删除、合并会影响 entry 的 tagIds/筛选；在同一事务更新关联，受影响 Entry revision 增加并写变更流，离线旧稿不得偷偷把删除的标签加回来。
5. 正文与附件引用都验证用户范围；FK 与应用层检查同时存在，不能只靠页面隐藏。
6. permanent purge 也要从保留中的快照、同步旧正文、回执和导出制品清除或失效相关内容；首版保守地在 purge 事务内提升该用户数据 generation，使旧同步游标、快照及导出均失效，客户端保护草稿后重新快照。旧 mutation 回执只返回“目标已永久删除”，不返回缓存正文。
7. 快照/导出等任务记录开始时的 generation；准备发布 ready/签发下载地址前，事务锁定当前用户状态并复核 generation 与未注销状态。purge/注销使运行中任务也失效；即使 worker 已读出旧正文，也不能稍后重新发布，暂存文件由清理任务收回。不能只删已经存在的制品而忽略在途任务。
8. schema 迁移脚本有版本号、升级测试和失败恢复计划；备份数据库时同步记录附件清单/版本，避免只有数据库没有照片。

## 9. 接口级验收用例

| 类别 | 必测行为 |
| --- | --- |
| 账号 | 大小写账号唯一、错误密码统一响应、中文昵称放 JSON 可正常请求、不出现验证码/Apple 分支 |
| 密码与恢复 | Unicode 密码边界、恢复码一次性、轮换丢响应再生成、改密撤销所有会话 |
| 身份与隔离 | 用户 B 猜用户 A 的 Entry/asset/export/session/snapshot ID 不能读写，过期 reauth 不可复用 |
| CSRF 与存储 | 跨站 Cookie 请求失败；Web 页面脚本拿不到 refresh Cookie；App 不落明文凭据 |
| 日记规则 | 空内容、非法日期、未知正文 schema、附件越权、同日并发创建都正确处理 |
| 幂等 | 服务端提交后断网重发只生效一次；同 ID 改 payload 返回冲突；失败事务不留半成品 |
| 事务排序 | 刻意延迟早序号事务，客户端仍不跳过变更；多对象事件本地一起应用 |
| 离线 | 编辑中退出、配额不足、旧确认后继续打字、增量先到确认晚到、多标签页并发、图片未上传都不覆盖新版本 |
| 快照 | 下载中继续编辑、分页超时、快照过期、90 天游标过期和 180 天旧队列处理 |
| 回收站 | 同日恢复冲突、并发删除/编辑、到期清理、永久删除旧 ID 不复活且衍生数据失效 |
| 标签 | 改名/删除/合并与其他设备离线编辑竞争，关系和计数不丢、不串账号 |
| 导出 | 生成中继续编辑、图片删除、worker 重启、超大数据、文件名转义、24 小时过期；worker 先读旧正文再遇 purge 后不得发布 |
| 注销与恢复 | 停用立即阻断访问、清理失败可重试、回执不能访问正文、恢复备份后不复活已删账户 |
| 待办 | 离线重试、完成重复任务、跨时区、提醒去重、动作未安装/被拒绝/参数非法均不误改完成状态 |
| 外部 App | 只有用户手势可执行白名单动作；任意 scheme、脚本、命令、敏感 URL 参数和服务端远程唤起均被拒绝 |
| 密码本 | 服务端/日志/普通导出无明文，错密码认证失败不返回可区分内容，nonce 不复用，锁定清内存，换钥/冲突/备份恢复可验证 |

验收记录要区分单元测试、API 集成测试、浏览器端到端、Android 真机、iOS 真机与正式部署。仅写好本契约或运行一次构建，都不能标记这些用例已通过。
