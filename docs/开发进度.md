## F15 固定上传操作与确认持久化（2026-09-08）

## F24 完整数据密钥轮换（2026-09-10）

迁移 `016_vault_key_rotation.sql` 增加有 24 小时有效期的轮换任务和分批暂存项。服务器按账号检查当前保险库配置版本、记录总数、每条记录版本和完整 ID 集合；每批最多 50 条，所有批次到齐后才在单个 PostgreSQL 事务中同时更新配置与全部密文。轮换期间若新增、删除或修改任何记录，提交会以 `ROTATION_ITEM_SET_CHANGED` 拒绝，并且不应用新配置或部分新密文。开始、分批和提交都使用持久固定请求编号，重复请求不会重复产生副作用。独立后台 worker 每小时清除全部账号已过期的任务及级联暂存项；创建新轮换时还会先清理当前账号，避免失效密文长期积累。运维健康接口会单独报告未及时清除的过期任务数。

客户端会先用旧数据密钥认证并解密全部记录；任一密文损坏即在准备阶段停止，不生成可激活的替换结果。成功准备后生成全新随机数据密钥、重加密全部记录并换发一次性恢复密钥。准备任务持久保存在账号隔离的 IndexedDB 或原生 SQLite 中，但在用户勾选“已保存新恢复密钥”之前不会上传或替换活动密钥；未确认时可以取消且原保险库保持不变。确认后保险库立即锁定，断网或提交响应丢失时由同步队列复用同一组请求编号继续；只有服务器返回完整提交结果后，本机配置和全部记录才在一个本地事务中原子切换。
