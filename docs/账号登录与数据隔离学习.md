# 账号登录与数据隔离：规则、关键字和实际代码

这份课程对应已接入页面的账号密码流程。它不表示日记云同步、手机安装包或全部 v2 功能完成。原来的 HTML 基础练习仍在根目录 `index.html`。

## 1. 先运行，再看代码

需要三个服务：网页、接口、数据库。各命令在项目根目录执行：

```powershell
npm run db:up
npm run db:migrate
npm run dev:api
```

保留后台终端，再开另一个终端：

```powershell
npm run dev
```

电脑打开 `http://127.0.0.1:4173/login`；“创建账号”进入注册，“忘记密码”使用保存过的恢复码。不会发送短信，没有 Apple 登录。

手机原生工程与网页共用这些页面，但还需要编译安装包、配置实际 HTTPS API 地址并做真机检查。根目录 `.env.example` 的 `VITE_API_BASE_URL` 注释给出了配置格式，不是可使用的真实服务。

## 2. 一个登录动作经过哪些地方

| 顺序 | 实际文件 | 负责什么 |
| --- | --- | --- |
| 1 | `apps/client/src/ui/auth-pages.js` | 标签、输入框、显示密码、错误提示；收集输入，不自己决定账号归属 |
| 2 | `apps/client/src/main.js` | 路由、保存旧草稿、登录后进入哪个数据空间 |
| 3 | `apps/client/src/services/auth-client.js` | 校验输入、发送 JSON、会话恢复、跨窗口协调；凭据不交给 UI 保存 |
| 4 | `apps/api/src/auth.js` | 再次校验、验证密码哈希、签发会话、校验权限 |
| 5 | `apps/client/src/ui/workspace.js` | 使用固定账号仓库写日记；旧账号的异步任务不能改用新仓库 |

前端校验帮助用户快速纠错；后端校验才是安全边界。不能因为网页上禁用了一个按钮，就认为接口已受保护。

## 3. HTML 表单的基本规则

```html
<form>
  <label for="username">账号</label>
  <input id="username" name="username" autocomplete="username" required>
  <label for="password">密码</label>
  <input id="password" name="password" type="password"
         autocomplete="current-password" required>
  <button type="submit">登录</button>
</form>
```

- `form`：把相关输入组合成一个提交动作。按回车也能提交。
- `label` 的 `for` 对应输入框的 `id`，点文字可聚焦，也便于读屏软件识别。
- `name` 是字段名称，不等于账号 ID；不能用用户输入的账号名拼接私有数据库归属。
- `type="password"` 只是遮住屏幕显示，不是加密。传输仍需要 HTTPS。
- `autocomplete="current-password"` 允许密码管理器填充旧密码；注册和新密码使用 `new-password`。
- 表单内非提交按钮要写 `type="button"`，否则“显示密码”可能触发提交。
- `required` 是浏览器提示。当前页面使用 `novalidate` 加统一中文错误，后端仍会验证。
- `aria-invalid="true"` 标记有错误的字段；`role="alert"` 让错误提示可被辅助工具发现。

当前代码通过 `h('input', {...})` 创建元素，和写 HTML 的含义相同；昵称和日记通过文本节点插入，不拼成可执行 HTML。

## 4. 本课必须理解的 JavaScript 关键字

| 写法 | 含义 | 使用规则 |
| --- | --- | --- |
| `const` | 不允许把变量重新指向其他值 | 对象内部字段仍可修改；不自动让对象不可变 |
| `let` | 允许重新赋值 | 用于会改变的状态，例如 `busy` |
| `import` / `export` | 模块的输入与输出 | 导出的名称与导入名称要对应；相对路径以当前文件为基准 |
| `async` | 函数返回 Promise | 不是自动并行；函数内部仍按书写顺序运行到下一个等待点 |
| `await` | 等待 Promise 成功或失败 | 等待时其他点击、窗口消息仍可能发生，不能假设账号不变 |
| `try` / `catch` / `finally` | 处理成功、错误及收尾 | `finally` 恢复按钮；不能在里面把失败写成成功 |
| `throw` | 中断当前流程并抛出错误 | 调用方应 `catch`，给出可操作提示 |
| `return` | 结束当前函数并返回结果 | Promise 成功不等于业务成功，要检查 HTTP 状态 |
| `?.` | 对空值安全访问 | `user?.id` 在没有 user 时为 undefined，不是合法身份 |
| `??` | 只在 null/undefined 时用默认值 | 与 `||` 不同，0 和空字符串不会被替换 |
| `...object` | 浅复制或展开对象字段 | 不是深复制，后面的同名字段覆盖前面的字段 |
| `===` | 不做隐式类型转换的相等比较 | `'1'` 与 `1` 不相等；API revision 有意使用字符串 |
| `Map` / `Set` | 键值映射 / 不重复集合 | 本项目分别缓存已打开的仓库、跟踪还没完成的写入 |
| `Object.freeze` | 禁止对象顶层字段修改 | 不冻结嵌套数据库对象；仓库仍可通过其方法正常写入 |

## 5. 账号名、密码、昵称不是同一种数据

- 账号名：3–32 位 ASCII 字母、数字和 `._-`，首位为字母或数字；去掉两端空格并转小写。
- 密码：新密码为 12–128 个 Unicode 字符，UTF-8 不超过 512 字节；不 `trim()`，因为空格也可能是密码的一部分。
- 昵称：可使用中文；通过 JSON 正文发送。
- 服务端用户 ID：服务器分配的 UUID，才用于账号数据空间。

例如 `validateCredentials({ username: ' Alice ', password: ' abc ' })` 的结果是账号 `alice`、密码仍为 ` abc `。登录阶段不以注册最小长度拒绝旧输入，而是由服务端验证；新注册和改密始终执行新密码规则。

## 6. 为什么原来会报 Headers 编码错误

请求头不能随意装入中文字符串。以下示例是错误方向：

```js
// 不要这样做：昵称不是访问凭据，也不能随便放进 Headers。
headers.set('Authorization', '我的中文昵称');
```

本项目只把服务端签发的 ASCII 凭据放入头；中文放进 JSON：

```js
await auth.updateProfile({
  displayName: '我的中文昵称',
  baseRevision: profile.revision,
});
```

`JSON.stringify()` 把对象变成传输字符串；服务端 `express.json()` 解析为对象。`baseRevision` 表示“我修改的是哪个版本”，不同窗口修改过资料后应刷新再改，不能静默覆盖。

## 7. Cookie、访问令牌、恢复码分别做什么

| 数据 | 作用 | 本项目保存位置 |
| --- | --- | --- |
| 密码 | 验证账号本人 | 输入期间仅在内存；服务端只保存 Argon2id 哈希 |
| access token | 短期调用受保护 API | 客户端服务闭包的内存，不写 localStorage |
| Web refresh 凭据 | 刷新短期访问令牌 | 服务端设置的 HttpOnly Cookie，页面 JS 读不到 |
| App refresh 凭据 | 原生 App 刷新会话 | 原生安全存储；禁止退回插件的 Web localStorage 模拟实现 |
| CSRF token | 保护使用 Cookie 的 Web 会话变更 | 从同源接口读取，用于对应请求；不当作用户 ID |
| 恢复码 | 忘记密码后重置 | 生成时仅显示一次；用户自行私密保存，服务端存摘要 |

`HttpOnly` 只表示页面脚本不能读取 Cookie，不代表不需要其他安全措施。服务端仍检查 Origin、CSRF、JWT、数据库会话及账号状态。

## 8. 为什么“换账号”不能只是改一个变量

假设 A 点了保存，网络还没返回，就登录 B。如果保存回调临时读取全局 `store` 或拿 B 的令牌重试，可能把 A 的内容放到 B。

本项目使用两层约束：

1. `createWorkspace({ repository })` 创建固定仓库的闭包。闭包就是函数保留创建时可访问的变量。A 的页面只能访问 A 创建时传入的仓库，不能换成 B 的仓库。
2. 每个 API 请求捕获 `userId + epoch`，刷新前、重试前、返回前检查。`epoch` 是一次登录代际；同账号重新登录也不是同一个代际。

Web 多标签通过 `navigator.locks` 串行修改会话，通过 BroadcastChannel 通知状态变化；通知后仍读取持久化描述，不能盲信可能延迟到达的消息。

切换流程先冻结并保存编辑器，等已开始的本机写入完成，再进入新仓库。旧页面销毁后，旧回调不能更新新页面路由。出现不能确认的会话响应时，保存 `refreshPending` 标记并要求重新登录，不自动重复使用可能已被消费的 refresh 凭据。

## 9. 三种空间，不能自动混合

| 空间 | 归属 | 当前行为 |
| --- | --- | --- |
| `learning` | 这台设备上的学习记录 | 未登录可用；不会自动导入账号 |
| `user:<服务端 UUID>` | 对应账号的本机副本 | 登录同一账号可再次打开；与其他账号分库 |
| `device` | 安装与会话协调元数据 | 不保存密码、访问令牌、恢复码或日记正文 |

Web 使用 IndexedDB；App 使用原生 SQLite 适配器。账号空间现已接入同步队列、版本与冲突处理，并支持显式预览和迁移学习数据。提前设置本机 PIN 后，网络或响应异常时可打开该账号的本机副本继续记录；此时不会上传、下载或执行账号安全操作，明确收到 401/撤销也不会允许离线进入。其他设备要看到新内容，仍需双方恢复联网并成功同步。

退出不自动删库；会话失效时遮住旧账号页面，并允许保存或导出救援备份。救援文件包含还没写入数据库的编辑器快照；用户确认文件可打开并包含当前草稿后，才能关闭未保存页面继续登录。备份为明文，包含私密日记，请自行确认下载成功。它不是端到端加密导出。

## 10. 自己动手验证

先用两个新测试账号，避免拿重要日记试验：

1. 未登录时写一篇学习日记，注册 A，确认 A 的时间线没有那篇学习日记。
2. A 写一篇，退出；登录 B，确认 B 看不到 A 的内容。
3. 再登录 A，确认 A 的本机内容仍在。
4. 在安全页生成恢复码并保存；刷新页面，旧码不能重新显示。
5. 新窗口登录另一个账号，旧账号页面应遮挡，而不是继续显示在线。
6. 修改中文昵称，确认没有 Headers 编码异常。

自动检查：

```powershell
npm test
npm run test:integration
npm run test:e2e
npm run test:auth-browser
npm run build
npm run mobile:sync
```

`test:integration` 与 `test:auth-browser` 只在专用本机 PostgreSQL 端口创建唯一临时库，完成后清理本次创建的库。浏览器测试使用另一个预览端口 4174，不重启你的 4173 页面。

单元测试包含 mock，浏览器测试包含手机尺寸模拟，资源同步只是拷贝构建内容。它们不能代替 Android/iOS 真机、安装包签名、公开 HTTPS 部署、云端同步和备份恢复的验收。
