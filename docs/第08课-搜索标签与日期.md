# 第 08 课：搜索、标签与日期筛选

## 1. 本课目标

本课学习三个概念：

1. 使用 `filter()` 和 `includes()` 查找数组记录。
2. 规范化文字和标签，组合多个筛选条件。
3. 使用防抖控制输入期间的重复计算。

启动：

```powershell
npm run learn:08
```

打开 <http://127.0.0.1:4184>。自动检查：

```powershell
npm run check:learn:08
```

本页使用六篇固定示例，不读取正式数据。

## 2. filter() 的规则

```js
const results = entries.filter((entry) => entry.title.includes('雨'));
```

`filter()` 依次调用判断函数，只把返回 true 的项目放进新数组。它不修改原数组。

```js
const oldEntries = entries.filter((entry) => entry.entryDate < '2026-09-01');
```

稳定的 `YYYY-MM-DD` 日期字符串可以直接比较先后。

## 3. includes() 是字面包含

```js
entry.title.includes('C++');
```

`includes()` 把 `+` 当普通字符，不当正则表达式语法。这适合日记搜索：用户输入的句号、括号、`+` 等应按字面查找。

它默认区分大小写，因此先规范化搜索词与候选文字。

## 4. 文字规范化

```js
function normalize(value) {
  return String(value ?? '')
    .normalize('NFKC')
    .trim()
    .toLocaleLowerCase('zh-CN');
}
```

- `String(value ?? '')` 把空值安全转成空字符串。
- `normalize('NFKC')` 统一部分视觉等价的 Unicode 写法。
- `trim()` 清除首尾空白。
- `toLocaleLowerCase()` 统一英文大小写。

规范化用于搜索和标签匹配，不应悄悄改写用户日记正文原文。

## 5. 建立可搜索文字

```js
const searchable = normalize([
  entry.title,
  entry.content,
  ...entry.tags,
].join('\n'));
```

标题、正文和标签组合为一个候选字符串。换行只是字段分隔，不会显示到页面。

正式大数据搜索不应每次拼接全部记录；可建立索引或让服务器查询。本课只有六条示例，重点是逻辑规则。

## 6. 标签集合与 Set

```js
const tags = new Set(['生活', '学习', '生活']);
console.log(tags.size); // 2
```

`Set` 只保留唯一值。生成标签选项：

```js
const tags = [...new Set(entries.flatMap((entry) => entry.tags))];
```

- `flatMap()` 把每篇记录的标签数组展开并合并。
- `new Set()` 去重。
- `[...set]` 把集合展开回数组。

生产标签还要按规范名处理大小写、全半角和并发创建，不能只靠页面去重。

## 7. some() 检查任一标签

```js
entry.tags.some((tag) => normalize(tag) === selectedTag);
```

`some()` 只要有一项返回 true，整体就返回 true。标签筛选是“该记录是否有任意一个标签等于所选标签”。

## 8. 组合筛选条件

```js
return (!query || searchable.includes(query))
  && (!tag || entry.tags.some((name) => normalize(name) === tag))
  && (!from || entry.entryDate >= from)
  && (!to || entry.entryDate <= to);
```

每个条件都使用“未填写就通过；填写后必须匹配”的模式。`&&` 表示所有已启用条件必须同时满足。

把判断放进命名函数 `matches(entry, filters)`，比在渲染函数中堆一整行更容易测试。

## 9. 日期区间验证

```js
if (from && to && from > to) {
  showError('开始日期不能晚于结束日期。');
  return;
}
```

无效区间不应静默显示“0 篇”，否则用户会误以为没有数据。页面明确显示规则错误，并保持原始记录不变。

## 10. 300ms 防抖

```js
let searchTimer;

function scheduleSearch() {
  clearTimeout(searchTimer);
  searchTimer = setTimeout(renderResults, 300);
}
```

用户连续输入时，旧计时器被取消；停止输入约 300ms 后才执行一次搜索。这叫 debounce。

筛选下拉框和日期选择通常在明确改变后立即执行，不需要同样防抖。

## 11. 清除筛选

```js
function resetFilters() {
  clearTimeout(searchTimer);
  queryInput.value = '';
  tagSelect.value = '';
  dateFrom.value = '';
  dateTo.value = '';
  renderResults();
  queryInput.focus();
}
```

清除所有条件后立刻重新渲染，并把焦点返回搜索框。只清页面控件但忘记渲染，会让结果与控件不一致。

## 12. 空结果不是错误

合法筛选可能没有匹配记录。页面应显示：

- 结果数量为 0。
- “没有符合条件”的空状态。
- 原记录未删除的说明。
- 可用的清除筛选按钮。

日期范围非法才是验证错误。这两个状态含义不同。

## 13. 安全渲染结果

结果卡继续使用：

```js
heading.textContent = entry.title;
content.textContent = entry.content;
```

高亮搜索词若需要插入多个节点，也应通过 `createTextNode()` 和受控 `mark` 元素构造，不能把用户查询拼进 `innerHTML`。

## 14. 性能边界

本地六条记录可以全量 `filter()`。正式产品达到 10,000 篇时还需要：

- 索引可搜索纯文本。
- 首屏限制数量并分页。
- 防抖和可取消查询。
- 在线查云端全量、离线查已下载内容。
- 记录测试样本和响应时间，不能只说“很快”。

当前正式产品已用 50 条首屏和 10,000 篇自动场景验证，但本课不复制其复杂仓储实现。

## 15. 常见错误

### 用正则解释用户输入

用户输入 `C++`、`[` 等可能造成语法错误或改变含义。普通搜索优先使用字面 `includes()`。

### 只规范化查询词

候选文字和查询词必须使用同一规范化函数。

### 修改原数组

筛选应该返回新数组，不删除不匹配记录。

### 无效日期显示空结果

应明确提示开始日期晚于结束日期，而不是让用户猜。

### 每个按键立即做昂贵查询

输入事件使用防抖；新查询开始时取消旧计时器。

### 空结果不提供恢复入口

始终保留清除筛选按钮，并说明原数据没有被删除。

## 16. 本课关键字

| 关键字 | 含义 |
| --- | --- |
| query | 用户输入的查询词 |
| filter | 只保留符合条件的项目 |
| literal search | 按普通字符含义搜索 |
| normalization | 把等价写法规整为统一形式 |
| Unicode | 表示世界文字字符的标准 |
| `includes()` | 判断字符串是否包含另一字符串 |
| `filter()` | 建立符合条件的新数组 |
| `some()` | 是否至少一项符合 |
| `Set` | 只保存唯一值的集合 |
| `flatMap()` | 转换后把一层数组展平 |
| debounce | 停止连续触发后再执行 |
| empty state | 合法但没有结果的界面 |
| combined filter | 多个条件同时筛选 |

## 19. 思考题与参考答案

1. 为什么普通搜索使用 includes 而不是直接建立正则？
   - includes 按字面处理标点，更符合普通用户预期，也避免无效正则和意外模式。
2. filter 会修改原数组吗？
   - 不会，它返回一个只包含匹配项目的新数组。
3. Set 在标签列表中解决什么问题？
   - 去除重复标签值，便于建立唯一筛选选项。
4. 为什么候选文字也要规范化？
   - 只规范查询词无法匹配大小写或 Unicode 写法不同的候选内容。
5. 防抖做了什么？
   - 连续触发时取消旧计划，只在用户暂停输入后执行最近一次搜索。
6. 为什么无效日期区间不是普通空结果？
   - 它违反输入规则，用户应修正条件；空结果则是合法条件下确实没有匹配。
