# 第 12 课：账号与密码安全

## 1. 本课目标

本课学习三个概念：

1. 密码只保存为慢速、有盐的 Argon2id 哈希。
2. 登录后使用随机、可撤销的服务器会话。
3. 忘记密码使用一次性高熵恢复码，不使用短信或第三方登录。

```powershell
npm run learn:12
```

打开 <http://127.0.0.1:4188>。自动检查：

```powershell
npm run check:learn:12
```

课程账号与正式日记账号完全隔离。

## 2. 本产品的登录边界

只提供：

- 账号注册。
- 账号＋密码登录。
- 当前会话退出。
- 一次性恢复码重置密码。

不提供短信验证码、手机号验证、Apple 登录或其他社交登录。手机号可以作为普通账号字符串，但系统不发送验证码，也不证明号码归属。

## 3. 规范化账号

```js
const username = String(value ?? '').trim().toLowerCase();
```

规则：3–32 位字母、数字、点、下划线或连字符，首位是字母或数字。注册和登录必须使用同一规范化方法，并由数据库 UNIQUE 再保护唯一性。

## 4. 密码规则

本课注册密码要求 12–128 个 Unicode 字符，同时限制 UTF-8 字节数不超过 512。长度只是最低边界，用户仍应使用独立且难猜的密码。

不要强迫定期改密，也不要设置会降低熵的“必须每 30 天更换”规则；发生泄露、复用或用户主动选择时再更换。

## 5. 绝不保存明文密码

```js
const passwordHash = await argon2.hash(password, {
  type: argon2.argon2id,
  memoryCost: 19456,
  timeCost: 2,
  parallelism: 1,
});
```

数据库只保存 `$argon2id$...` 字符串。Argon2id 自带随机 salt；验证使用 `argon2.verify(hash, password)`。

哈希不是加密：无法“解密取回”原密码。忘记密码只能验证恢复凭据后设置新密码。

## 6. 为什么普通 SHA-256 不适合密码

SHA-256 很快，攻击者能高速猜测大量密码。密码哈希应故意消耗时间和内存，并使用每条随机盐。

SHA-256 可用于本课的高熵随机会话令牌摘要，因为令牌不是人类可猜密码；用途不同，算法选择也不同。

## 7. 通用登录错误

```text
账号或密码不正确
```

不存在账号和密码错误返回相同消息，避免公开账号是否注册。内部仍可使用安全审计指标，但不能记录明文密码。

## 8. 失败限速

本课按 IP＋规范化账号统计一分钟内失败次数，达到 5 次返回 429。

生产限速需要共享存储或网关，单进程 Map 无法覆盖多实例；还要设计恢复、误伤、代理地址和告警策略。

## 9. 随机会话令牌

```js
const token = randomBytes(32).toString('base64url');
```

客户端得到随机令牌，数据库只保存其 SHA-256 摘要。数据库泄露时，摘要不能直接作为 Cookie 使用。

每次登录创建独立会话 ID，可单独撤销，不使用永久不变的“用户令牌”。

## 10. HttpOnly Cookie

```js
serialize('lesson12_session', token, {
  httpOnly: true,
  sameSite: 'strict',
  path: '/',
  maxAge: 7 * 86400,
});
```

- HttpOnly：页面 JavaScript 不能读取。
- SameSite=Strict：限制跨站请求携带。
- Path=/：明确 Cookie 作用路径。
- Max-Age：会话有效期。

生产 HTTPS 还必须设置 Secure。SameSite 不是全部 CSRF 防护，正式网页使用 Origin/CSRF 令牌等额外措施。

## 11. 服务端认证

每个受保护请求：

```text
读取 Cookie → 哈希随机令牌 → 查询未过期会话 → 查询 active 用户 → 建立 principal
```

服务器不能仅解码客户端 userId 就相信身份。撤销会话后，旧令牌必须立即无法访问 `/api/me`。

## 12. 恢复码

```js
const recoveryCode = randomBytes(24).toString('base64url');
```

24 随机字节提供 192 位熵，Base64URL 后为 32 字符。明文只在创建或重置时返回一次，数据库只保存摘要。

恢复码与密码本恢复密钥是两套系统：账号恢复码重置登录密码；密码本恢复密钥解开客户端加密的数据密钥，二者不能替代。

## 13. 一次性消费与事务

重置密码在一个数据库事务中：

1. 核对当前恢复码摘要。
2. 写入新密码哈希。
3. 换发新的恢复码摘要，使旧码失效。
4. 删除该用户全部旧会话。
5. 提交事务。

任一步失败都回滚，不能出现密码已改但旧会话未撤销的半完成状态。

## 14. 恢复响应的安全界面

恢复码只显示一次。用户必须确认已离线保存，才能关闭提示。刷新后服务器不再返回同一明文。

不要截图上传公共云盘，也不要与密码保存在同一个未加密文档。正式使用可放入可信密码管理器或离线介质。

## 15. 注销与退出不同

- 退出登录：撤销当前会话，账号和数据保留。
- 退出其他设备：撤销选定会话。
- 注销账号：停用账号并进入持久删除流程。

本课只实现当前会话退出。正式产品对注销有密码再验证、回执和后台清理队列。

## 16. 数据库里允许保存什么

`users`：用户 ID、规范化账号、密码哈希、恢复码摘要、状态、创建时间。

`sessions`：会话 ID、用户 ID、令牌摘要、创建和到期时间。

不保存明文密码、明文恢复码，也不把 Cookie 令牌写入日志。

## 17. 当前课程限制

本课仍不是生产认证系统：

- 本机 HTTP，Cookie 未设 Secure。
- 限速只在单进程内存。
- 没有邮件或人工恢复渠道。
- 没有完整 CSRF、防自动化和安全审计部署。
- SQLite 不适合正式多实例服务。

正式产品对应实现使用 PostgreSQL、短访问令牌、刷新会话、CSRF、幂等安全操作和设备管理，并有独立集成测试。

## 18. 常见错误

### 保存明文或可逆加密密码

密码只能验证，不需要取回；使用密码哈希。

### 使用快速哈希

SHA-256 等通用快速哈希不适合人类密码。

### 在 localStorage 保存会话令牌

网页会话优先使用 HttpOnly Cookie，减少脚本直接读取令牌的风险。

### 登录错误暴露账号存在

不存在和密码错误使用相同外部消息。

### 恢复码可重复使用

成功消费后必须原子换发并使旧码失效。

### 改密后旧会话仍有效

密码重置应撤销既有会话，要求重新登录。

## 19. 本课关键字

| 关键字 | 含义 |
| --- | --- |
| authentication | 确认用户身份 |
| authorization | 判断身份是否有权限 |
| password hash | 不可逆验证密码的哈希 |
| salt | 每条密码哈希的随机输入 |
| Argon2id | 内存困难型密码哈希算法 |
| session | 可创建、过期和撤销的登录状态 |
| token | 随机会话凭据 |
| digest | 令牌或恢复码的固定摘要 |
| HttpOnly | 禁止页面脚本读取 Cookie |
| SameSite | 限制跨站携带 Cookie |
| Secure | 只通过 HTTPS 发送 Cookie |
| recovery code | 一次性高熵账号恢复凭据 |
| rate limit | 限制短时间尝试次数 |
| revocation | 使会话立即失效 |
| CSRF | 利用浏览器身份发起非预期请求的攻击 |

## 20. 动手任务

1. 注册练习账号，离线记录恢复码。
2. 退出后用错误密码登录，观察通用错误。
3. 使用正确密码登录。
4. 用恢复码设置新密码，验证旧密码和旧会话失效。
5. 再次使用旧恢复码，确认被拒绝。
6. 在数据库中只读查看 password_hash 和 recovery_digest，确认没有明文。
7. 运行自动检查。

## 22. 思考题与参考答案

1. 为什么密码不能使用可逆加密保存？
   - 服务器只需验证密码，不需取回；可逆密钥泄露会暴露全部密码。
2. 为什么 SHA-256 不适合人类密码？
   - 它太快，攻击者可高速猜测；Argon2id 故意消耗时间与内存。
3. HttpOnly 解决什么问题？
   - 页面 JavaScript 无法直接读取 Cookie 值，降低令牌被脚本窃取的风险。
4. 改密为什么撤销旧会话？
   - 旧设备或已泄露会话不应在凭据恢复后继续访问。
5. 恢复码为什么只显示一次？
   - 服务端不保存明文，减少长期泄露面；丢失后只能在仍有权限时换发。
6. 账号恢复码能解密密码本吗？
   - 不能。密码本使用独立客户端数据密钥和恢复密钥，服务端账号恢复不持有它。
