# 第 06 课：表单与输入验证

## 1. 本课目标

本课学习三个概念：

1. 用 HTML 属性声明输入的基础规则。
2. 用 JavaScript 检查跨字段和业务规则。
3. 把错误信息准确关联到对应控件。

启动隔离练习：

```powershell
npm run learn:06
```

打开 <http://127.0.0.1:4182>。自动检查：

```powershell

```

练习数据只存在内存，不进入正式日记空间。

## 2. 表单的基本结构

```html
<form id="entry-form" novalidate>
  <label for="entry-title">标题</label>
  <input id="entry-title" name="title" required maxlength="80">
  <button type="submit">保存</button>
</form>
```

- `form` 把一组输入和提交行为关联起来。
- `label for` 与控件 `id` 相同。
- `name` 是提交或通过 `form.elements` 读取时使用的字段名。
- `type="submit"` 触发表单的 submit 事件。
- `novalidate` 在本课关闭浏览器默认气泡，由我们统一显示可测试的中文错误；规则仍保留在 HTML 中。

## 3. 常用 HTML 验证属性

| 属性 | 作用 |
| --- | --- |
| `required` | 必填 |
| `minlength` | 最少字符数 |
| `maxlength` | 最多字符数 |
| `min` / `max` | 数值或日期边界 |
| `pattern` | 正则表达式格式 |
| `type="email"` | 电子邮件格式 |
| `type="date"` | 日期选择控件 |
| `autocomplete` | 告诉浏览器字段用途 |

客户端验证改善体验，但不能代替服务器验证。用户可以绕过网页直接请求 API，正式后端必须再次检查所有输入。

## 4. 为什么不能只依赖 `required`

`required` 能拒绝真正的空值，但字符串可能只有空格：

```js
const title = titleInput.value.trim();
if (title.length < 2) {
  // 显示错误
}
```

日记日期不能晚于今天、密码和确认密码必须相同等业务规则，也需要 JavaScript 或服务器逻辑。

## 5. 清楚定义规则

本课规则是：

- 标题：去除首尾空白后 2–80 个字符。
- 日期：必填，不晚于设备今天。
- 心情：可选，只能选一个。
- 正文：去除首尾空白后 5–5000 个字符。

规则应先写成可读文字，再实现代码和测试。不要让用户通过不断试错猜规则。

## 6. 日期格式

`input[type=date]` 的 `.value` 使用 `YYYY-MM-DD`：

```js
const today = new Date().toLocaleDateString('en-CA');
dateInput.value = today;
dateInput.max = today;
```

ISO 日期字符串在同一格式下可按字典顺序比较：

```js
if (dateInput.value > today) {
  // 未来日期
}
```

正式多端产品还必须明确时区。不要用 UTC 日期无意中把本地深夜归到前一天或后一天。

## 7. Radio 单选组

```html
<fieldset>
  <legend>心情</legend>
  <label><input type="radio" name="mood" value="happy"> 开心</label>
  <label><input type="radio" name="mood" value="calm"> 平静</label>
</fieldset>
```

相同 `name` 让浏览器保证只能选一个。`fieldset` 和 `legend` 为整组控件提供可访问名称。

读取选择值：

```js
const selectedMood = form.elements.mood.value;
```

未选择时得到空字符串。

## 8. 错误信息如何关联控件

```html
<input id="entry-title" aria-describedby="title-hint title-error">
<p id="title-hint">2–80 个字符。</p>
<p id="title-error" role="alert" hidden></p>
```

出现错误时：

```js
titleInput.setAttribute('aria-invalid', 'true');
titleError.textContent = '标题至少需要 2 个字符。';
titleError.hidden = false;
```

- `aria-invalid="true"` 表明该控件当前无效。
- `aria-describedby` 把提示和错误文字关联给控件。
- `role="alert"` 让新增错误能被辅助技术及时感知。
- 红色只用于辅助，文字才说明真正问题。

## 9. 可复用的错误函数

```js
function fieldError(input, message) {
  const error = document.querySelector(`#${input.id.replace('entry-', '')}-error`);
  input.setAttribute('aria-invalid', String(Boolean(message)));
  error.textContent = message;
  error.hidden = message === '';
  return message !== '';
}
```

输入是控件和消息，输出是“是否存在错误”的布尔值。函数同时更新语义状态和可见文字。

真实大型表单可使用显式字段配置，不要依赖复杂命名猜测；本课保持规则最小且可看懂。

## 10. 找到第一个错误

```js
const firstInvalid = [
  titleInvalid && titleInput,
  dateInvalid && dateInput,
  contentInvalid && contentInput,
].find(Boolean);

firstInvalid?.focus();
```

数组按页面顺序保存可能错误的控件，`.find(Boolean)` 找到第一个真值。`?.` 是可选链：没有错误时不会调用 `focus()`。

提交失败后应把焦点移到第一个错误，不能只在页面底部显示“失败”。

## 11. 实时验证的边界

用户每输入一个字符就显示红色错误会令人紧张。本课策略：

- 第一次提交前只显示帮助文字和计数。
- 提交后显示明确错误。
- 用户继续输入时清除该字段旧错误。
- 再次提交时重新完整验证。

正文字符计数不是错误：

```js
contentCount.textContent = `${contentInput.value.length} / 5000`;
```

## 12. 保存经过验证的数据

```js
function saveEntry(event) {
  event.preventDefault();
  if (!validateForm()) return;

  const title = titleInput.value.trim();
  const content = contentInput.value.trim();
  // 此处才进入保存步骤
}
```

先验证，再构建对象或写入存储。不要先保存不合法数据，再尝试修补。

即使验证通过，写入存储也可能失败；正式应用还要单独处理空间不足、事务失败和同步冲突。

## 13. 客户端与服务器的责任

```text
HTML 约束
  → 提供控件语义和基础边界
JavaScript 验证
  → 即时、友好的业务提示
服务器 schema
  → 不信任客户端，再次拒绝非法数据
数据库约束
  → 保护唯一性、引用和最终一致性
```

四层职责不同，不能只做其中一层就声称数据安全。

## 14. 常见错误

### 使用 placeholder 代替 label

placeholder 输入后消失，也不能稳定提供控件名称。保留可见 label。

### 只把边框变红

必须提供文字，说明哪个规则没有满足。

### 所有错误显示在页面顶部

可以有汇总，但每条错误仍应与对应字段关联。

### 修改输入后不清除旧错误

用户会误以为修改无效。输入变化后先清除旧提示，提交时再验证。

### 相信客户端验证

请求可以绕过页面。服务器必须使用同等或更严格规则。

### 用设备 UTC 代替本地日记日期

深夜时可能产生日期偏移。日期规则必须明确使用哪个时区。

## 18. 思考题与参考答案

1. 为什么同时写 HTML 约束和 JavaScript 验证？
   - HTML 提供语义和基础边界；JavaScript负责友好的业务规则与错误呈现，两者互补。
2. 为什么还需要服务器验证？
   - 客户端代码和请求都能被修改或绕过，服务器不能信任输入。
3. `aria-describedby` 有什么作用？
   - 把提示和错误元素与输入控件关联，辅助技术可在操作控件时读取说明。
4. 为什么提交失败要聚焦第一个错误？
   - 用户能立即知道从哪里开始修正，尤其有利于键盘和屏幕阅读器操作。
5. 为什么日记日期要明确时区？
   - UTC 与用户本地日期可能不同，不明确会把深夜记录归错日期。
6. 为什么不从第一下输入就持续报错？
   - 用户尚未完成输入，过早报错会造成干扰；先帮助、提交后验证更友好。
