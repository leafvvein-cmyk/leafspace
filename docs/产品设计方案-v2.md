# 日记本产品设计方案 v2

版本：2026-09-08 · 状态：待实施的设计基线，不是功能完成报告。

## 1. 产品定位与已确定的范围

做一个适合每天写作的私人日记本：电脑上安静地长篇书写，手机上随时记录，登录同一个账号后同步。

用户已确认电脑端采用“浏览器使用，并可安装到桌面”。本方案的交付物为：

| 终端 | 交付形态 | 主要用途 |
| --- | --- | --- |
| 电脑 | 响应式网站 + 可安装 PWA，优先验证 Windows Chrome / Edge | 长篇编辑、整理、搜索、导出 |
| Android | Capacitor 打包的安装 App，测试 APK、发行 AAB | 随手记录、拍照、离线写作、提醒 |
| iOS | Capacitor 打包的 App，先 TestFlight 测试再发行 | 与 Android 同一套功能，适配 iPhone 和 iPad |

PWA 安装后可以从桌面或开始菜单打开独立窗口；其数据仍受浏览器存储机制管理。手机 App 使用原生容器承载网页界面，并通过插件调用设备能力，属于混合应用。电脑端本期不另做独立 EXE。依据：[Edge PWA 文档](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/how-to/)、[Capacitor 概览](https://capacitorjs.com/docs)。

认证固定为账号 + 密码；没有手机号验证码、Apple 登录或其他第三方登录。内容默认只有本人可见。暂不加入社区、公开分享、AI 写作、付费会员，集中完成之前约定的个人日记体验。

当前工作区只有教学文档和一个基础 `index.html` 练习。旧版完整应用不在当前目录，不能假定以前的接口、数据库或 App 安装包仍可复用。实施时先核实任何找到的旧数据，不自动覆盖或导入。

阅读顺序：本文件 → [页面与导航设计](页面与导航设计-v2.md) → [接口与数据设计](接口与数据设计-v2.md)。

## 2. 设计原则

1. 写作优先：首页打开今天，正文编辑区是视觉中心。
2. 保存可信：分别显示“已保存在此设备”和“已同步”，写入失败不能冒充成功。
3. 内容归本人：每个数据请求都校验所属账号；退出、切换账号、设备锁定均有明确状态。
4. 两端一致但布局不同：数据、编辑格式和操作规则共用，导航和工具栏适配终端。
5. 学习可以循序渐进：HTML、CSS、原生 JavaScript 打底，用成熟库处理富文本和存储等复杂问题。

## 3. 视觉方向：温暖纸张与安静书写

工作名称暂用“日记”，品牌名称不影响数据和接口。

| 项目 | 建议规范 |
| --- | --- |
| 背景 | 浅米白 `#F7F3EC`，卡片 `#FFFCF7`，减少重阴影 |

## 4. 推荐技术与选择理由

| 层 | 方案 | 实现责任及边界 |
| --- | --- | --- |
| 页面 | HTML + CSS + 原生 JavaScript ES Modules，Vite 开发构建 | 保留基础编码可读性；按页面、组件、服务拆模块，避免一个巨型脚本 |
| 编辑器 | Tiptap 开源核心与必要扩展 | 用原生 JS 初始化，支持结构化 JSON、列表和历史记录；不依赖付费云协作 |
| 手机容器 | Capacitor | 共用构建产物，提供 Android / iOS 原生工程和设备适配层 |
| 电脑本地库 | IndexedDB，使用 Dexie 简化事务 | 日记、草稿、待同步队列、图片 Blob；不把正文装入 localStorage |
| 手机本地库 | SQLite 适配器 + App 私有文件目录 | 日记与队列事务写入，照片与缩略图落私有目录；插件在 M0 验证兼容性 |
| API | Node.js + Express + Zod | 路由、输入校验、权限、业务服务分层；JSDoc/共享 schema 辅助初学者 |
| 服务端数据 | PostgreSQL | 账号、日记、会话、同步变更持久化，事务和唯一约束保护数据 |
| 图片 | 私有对象存储，国内部署可选 OSS | API 签发短期上传凭据和读链接，桶不公开 |
| 任务 | 第一版 PostgreSQL 任务表 + 单独 worker | 导出、回收站清理、账户清理；任务有重试和状态，不依赖 API 内存定时器 |
| 发布 | Web 静态资源 + 同源 `/api/v1` 反向代理；App 内置同版资源 | 测试与生产数据分开；安装包有版本和签名 |

Tiptap 官方提供原生 JavaScript 接入方式，因此无需为了富文本先学习 React。[官方接入说明](https://tiptap.dev/docs/editor/getting-started/install/vanilla-javascript)

IndexedDB 支持结构化数据和事务，适合作为离线库。[MDN IndexedDB](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)

与旧学习路线的衔接：`localStorage` 和单机 SQLite 仍可作为练习，但正式多端版本的服务器直接用 PostgreSQL；手机 SQLite 是设备本地副本。这样不会把学习演示中的存储限制带入正式日记。

## 6. 关键业务规则

### 6.1 日期与每日一页

时间戳一律用 UTC，日记日期独立用 `YYYY-MM-DD`，另记 IANA 时区，默认 `Asia/Shanghai`。日期由创建时用户选择，不因旅行或设备改时区重新计算。每日可补写；随记保留精确发生时间。

用户在“今天”点每日记录时：本地已有则打开，没有则先出现空编辑稿；输入内容后才创建。两台设备离线创建同日记录时，服务端返回已有每日 ID，本地稿保留并进入冲突处理，不能丢弃后一份。

### 6.2 本地保存和云端同步

输入停止约 500ms，草稿、entry 副本和队列在同一事务写入；连续输入时最多约 2 秒安排一次快照，输入法组合期间避免重建编辑 DOM。具体阈值是体验初值，真机测试后调整。

成功落盘后显示“已保存在此设备”；服务器确认后才显示“已同步”。磁盘空间不足、事务失败必须显示“保存失败，请复制或导出内容”，保留当前编辑器文本。

Web 多标签页以数据库写锁/版本检测和广播选出单一同步执行者，防止多个页面争抢刷新令牌和队列。手机进入后台前尽力落盘，不能把可靠性寄托在应用关闭事件。

### 6.3 同步与冲突

客户端上传 `{mutationId, entryId, baseRevision, operation, payload}`，服务器只接受版本匹配的修改。上传去重、内容写入、版本递增、变更日志写入在同一事务完成。重试相同请求不生成第二篇日记。

先实现保守冲突处理：展示“本机草稿 / 云端版本”，可保留云端、另存本机为随记或手工合并后提交最新版本。用户处理前不删除本地稿，不以最后更新时间自动覆盖正文。自动块级合并只在后续有充分测试后考虑。

首次设备登录下载稳定快照，随后按序号增量更新。过旧游标需要重建云端镜像时，先隔离保留所有待同步稿，再重建；具体同步协议见接口文档。

### 6.4 账号、离线与设备锁的区别

账号密码证明“可以访问哪份云端数据”；本地设备锁限制“这台设备现在是否展示已有内容”。第一次登录需要网络。服务器撤销设备只能阻止后续联网请求，无法即时擦除正在离线的设备副本；设备重连收到失效响应后锁定，不自动把本机未同步数据上传到别的账号。

本地数据库和缓存均以账号 ID 隔离。切换账号前先完成本地落盘；有待同步数据时提供“同步后退出 / 导出后退出 / 暂不退出”。确认移除本机数据后，只清理对应账号空间，保留主题等非敏感设置。

### 6.5 隐私与密码

新服务使用 Argon2id 保存密码哈希，带独立随机盐；参数初值按官方安全建议并以服务器压测调整，不自己设计哈希算法。[OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

传输 HTTPS、私有图片桶和服务端磁盘/备份加密是第一版的保护措施。服务端能处理正文搜索和导出，因此第一版不称为端到端加密。若将来需要服务器也无法读取正文，必须单独设计密钥恢复、客户端搜索和导出流程。

手机刷新凭据和本地加密密钥使用 Keychain / Android Keystore 保护的存储适配器；数据库和图片缓存需一起纳入本地保护验收。网页 PIN 是界面锁，不承诺阻止拥有本机浏览器调试权限的人读取 IndexedDB。生物识别不可用时使用已配置的设备凭据/PIN或在线重新验证。

M1 在登录系统接入前产生的数据位于独立的“本机学习空间”，不能自动归给下一位登录用户。M2 提供明确的首次迁移确认：预览篇数与目标账号，允许导出、保持独立或复制到指定账号；复制生成新 ID，daily 撞日期时进入冲突处理。未完成迁移前保留源数据，禁止因为创建账号而清空练习稿。正式发布版首次使用要求在线登录后建立对应账号空间。

Preferences 只用于轻量偏好；官方说明它不是本地数据库。本方案不把它当作安全密钥库或日记库。[Capacitor Preferences](https://capacitorjs.com/docs/apis/preferences)

### 6.6 搜索

服务器从结构化正文提取 `plainText`，首版做转义后的字面子串匹配；PostgreSQL `pg_trgm` 索引加速适合的 `ILIKE` 查询，短中文查询可能不能有效使用索引，需要限制到用户范围并压测，不能宣称已有中文智能分词。[PostgreSQL pg_trgm](https://www.postgresql.org/docs/current/pgtrgm.html)

离线同样做字面匹配，仅显示已下载内容。标签改名通过 tag ID 关联立即影响筛选；合并同名标签在一个事务中改关联，避免孤立记录。

### 6.7 待办与外部 App 动作

待办与日记分表、分路由，但可以通过只保存 ID 的关系关联某篇日记。任务包含标题、备注、截止时间及时区、优先级、完成状态、可选重复规则、子项和提醒设置；离线修改进入独立同步队列，不能把日记 mutation 当作待办接口复用。

每个待办可以配置零到多个“动作”。第一版只接受固定枚举，例如打开站内页面、打开 HTTPS 链接、唤起已登记的外部 App；不接受任意 JavaScript、命令行、文件路径或用户自行拼接的协议。打开企业微信等外部 App 时，由用户点击触发，客户端先校验动作类型、目标和参数，再调用 Capacitor App Launcher 或浏览器受限的外部链接能力。平台不支持、目标 App 未安装或系统拒绝时，保留待办原状态并显示可理解的备用操作。

企业微信的具体 scheme、Universal Link/App Link、目标页面、参数和授权方式等待后续需求确认后单独登记。敏感凭据不得放入 URL、待办正文、通知或日志；自动提醒也不得在后台静默打开外部 App。

### 6.8 密码本安全边界

密码本的业务对象是“App/网站登录记录”。解密后的条目包含类型（App/网站）、服务名称、登录账号、密码、网站登录地址或 App 标识、备注和可选收藏状态；同一个 App 或网站允许保存多个不同账号。服务名称、账号、地址、备注和收藏同样属于敏感信息，必须与密码一起放入加密载荷，不能作为服务端明文索引。

密码本使用独立“保险库密码”，不直接复用登录密码。首次创建时在客户端生成随机保险库数据密钥；保险库密码经带独立盐和版本化参数的 Argon2id 派生包装密钥，再使用经过审查的认证加密算法包装数据密钥。每条记录使用独立随机 nonce 加密，服务端只同步密文、nonce、算法版本、修订号和最小必要索引，不获得保险库密码、数据密钥或明文。

保险库默认自动锁定，回到后台和任务切换预览时先遮挡；查看、复制、修改或删除敏感字段要求保险库已解锁。手机可用 Keychain/Android Keystore 保护的设备密钥缩短再次解锁，但生物识别不是云端恢复方案。剪贴板定时清理只能尽力执行，页面必须说明系统或其他应用可能先读取内容；密码不得进入通知、崩溃报告、分析事件、普通日记导出或搜索索引。

忘记保险库密码时，账号密码重置不能解密旧保险库。创建密码本时生成独立 256 位恢复密钥并只显示一次；服务器只保存由该密钥经 AES-GCM 包装的数据密钥。用户可复制或下载后与加密备份分开保管；使用恢复密钥设置新密码或主动换发后会生成新恢复密钥，旧密钥立即失效。旧密码本解锁后可补生成恢复密钥。密码本在未完成外部密码学审查和真机测试前仍不得标记为可用于唯一的重要凭据副本。

## 7. 页面导航概要

电脑侧栏：今天、待办、时间线、日历、搜索、标签；底部密码本、回收站、同步中心、设置。主内容使用列表+详情布局，正文获得最大空间。密码本入口在锁定时不显示任何条目摘要。

手机底栏：今天、待办、时间线、我的；日历从今天页顶部进入；搜索按钮放各列表页顶部，新建按钮根据当前模块打开日记或待办菜单。编辑器全屏，底栏隐藏，返回时先落盘；日历、标签、密码本、回收站、同步中心在“我的”。

登录 →（首次恢复码设置）→ 今天 → 编辑 → 本地保存 → 同步；日历、时间线、搜索、标签都能进入同一篇阅读页，返回恢复来源页面状态。所有路由、页面组件及错误状态见页面文档。

    src/pages/            today、timeline、calendar、settings 等

packages/
  contracts/              schema、枚举、错误码
  sync/                   不依赖 UI 的同步队列与冲突逻辑

复用业务规则，不强求复用每个系统操作：`DiaryRepository` 提供事务增删查，Web 用 IndexedDB、手机用 SQLite；`MediaPicker`、`NotificationService`、`SecureSessionStore`、`LocalLock` 各有平台实现。

开发脚本、依赖和锁文件在实施阶段生成并锁定实测版本。M0 必须验证 SQLite、系统密钥存储、生物识别、相册、通知插件与同一 Capacitor 主版本能在两套原生工程共同构建；社区插件不能直接当成官方内置功能。若暂缺 iOS 构建资源，可继续 Web/Android 开发，但 M0 的 iOS 验证必须标记未完成，不能视为手机技术方案已全部通过。

M0 的工程和插件验证由助手协助完成并提供检查结果；用户课程仍从 HTML、CSS、JavaScript 的小模块推进，不要求第一课理解原生工具链、数据库迁移和完整安全协议。

## 9. 手机原生能力和交付限制

| 能力 | 手机实现 | 电脑对应 |
| --- | --- | --- |
| 相册/拍照 | Capacitor Camera + 原生照片选择器；点击时才申请必要权限 | 文件选择/拖入图片 |
| 通知 | 本地通知，权限拒绝展示说明；按设备时区重排提醒 | 首版前台提醒；应用关闭后的 Web Push 另列扩展 |
| 离线文件 | App 私有目录，缓存大小可查看和受控清理 | IndexedDB Blob，导出走浏览器下载 |
| 生物识别 | 经过验证的原生适配器 | 首版 PIN 界面锁或在线密码解锁 |
| 返回/键盘 | Android 返回键、iOS 手势、键盘遮挡和安全区适配 | 浏览器返回、快捷键和焦点管理 |
| 更新 | 新安装包兼容本地数据库迁移，迁移前保护草稿 | 提示有新版本，保存后用户点更新 |

相册与本地通知能力依据：[Camera](https://capacitorjs.com/docs/apis/camera)、[Local Notifications](https://capacitorjs.com/docs/apis/local-notifications)。通知实际送达受系统权限、电量和调度限制，页面不能承诺精确到秒。后台持续同步也不作跨平台承诺，以应用启动、回到前台、网络恢复时同步为基线。

当前电脑为 Windows，可以开发网站和 Android；iOS 原生编译与签名需要 macOS/Xcode 或可用的 macOS 构建服务及签名资源。导出网页 JS 不等于 iOS App 已构建。本方案依据 [Capacitor 环境要求](https://capacitorjs.com/docs/getting-started/environment-setup)，实施时再次核对版本匹配。

## 11. 关键验收场景

| 场景 | 必须观察到的行为 |
| --- | --- |
| 两个账号请求相同日记 ID | 另一账号收到 404，列表、图片、导出同样隔离 |
| 断网输入后强关 | 最近成功落盘文本保留，重新打开可继续写 |
| 两端同时修改同篇正文 | 出现可处理的冲突，本地和云端都能找回 |
| 两端同日各创建 daily | 一份成为每日，另一份稿进入合并/另存，无静默丢失 |
| 服务端成功但客户端超时重发 | 相同 mutation 只生效一次 |
| 图片未上传，文字已保存 | 文本正常可读；占位显示图片等待，不显示“全部同步” |
| 删除后旧设备再次上传 | 不复活被永久删除 ID；本机稿可另存为新 ID |
| 已登录设备被远程退出 | 下一次 API 调用被拒绝；离线副本在重连后锁定 |
| 用户写到一半有 PWA 更新 | 显示更新提示，保存后再刷新，不强制导航 |
| 清理缓存 | 区分可重下的资源与未同步稿，不删除后者 |
| 登录页面版本核验 | 只显示账号和密码，页面关于处可见 buildId，消除旧缓存误判 |
| 原生回归 | 测试安装包中的键盘、返回手势、权限、后台恢复，而不只验证网页构建 |

性能目标（验收目标，不是现有指标）：普通个人规模 10,000 篇时首屏列表 50 项，输入无明显卡顿；本地保存状态通常 1 秒内反馈；联网轻量列表请求在约定测试环境 p95 < 500ms。搜索、图片和全量导出分别压测，记录样本、机型和网络条件。

本次交付设计文件，不启动重建、安装原生工具链、申请云服务或覆盖用户练习。下一步开发可以从 M0 的“今天页 + 编辑器”开始，但应以接口文档的数据字段命名，减少后续返工。
